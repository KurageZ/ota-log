# 统计自定义功能设计

> 状态：已实现。
>
> 本文定义统计页顶层 section 的显示、隐藏、排序、设置入口、偏好兼容、时间范围和按需加载规则。统计指标本身的口径继续以现有代码和数据设计文档为准。

## 背景

统计页当前提供六个顶层 section。随着统计内容增加，固定布局会带来两个问题：

1. 不同用户关注的信息不同，但无法隐藏低关注内容或调整浏览顺序。
2. 即使用户不需要某类统计，页面仍会执行对应查询。

首页已经具备成熟的拖拽配置模型。统计自定义沿用这套交互，并使用「显示 / 隐藏」分区直接表达页面结果；配置对象只覆盖统计页的顶层 section，不拆分 section 内部的指标、图表和排行。

## 目标

- 用户可以显示、隐藏和排序统计页的顶层 section。
- 周、月、年、自定义和全部时间共用同一套布局，切换范围时页面结构保持稳定。
- 隐藏 section 后不执行仅由该 section 使用的查询。
- 设置入口位于统计页本身，不放入全局设置中心。
- 兼容未来新增 section，不破坏已有用户整理好的布局。
- 与首页自定义保持一致的拖拽、即时保存和还原体验。

## 非目标

- 不做自由布局编辑器。
- 不允许拆分或排序 section 内部的指标、图表、排行和卡片。
- 不为不同统计周期保存不同布局。
- 不支持修改 section 的颜色、样式或标题。
- 不将统计布局偏好纳入业务数据、数据库 migration 或备份恢复。
- 不因为某个 section 暂时无数据而自动隐藏或修改用户配置。

## 可配置 section

当前包含以下六项：

| 类型 | 用户可见名称 | 当前包含内容 |
|------|--------------|--------------|
| `activity` | 活动 | 活动状态数量、月度数量分布、常去城市与场地、团体活动排行 |
| `activityHeatmap` | 活跃度 | 按日期展示年度已完成活动与拍立得综合热力图 |
| `oshi` | 单推 | 相关活动、单推拍立得、最近活动、月度活跃 |
| `spending` | 支出 | 总支出、场均支出、门票与拍立得支出、支出最高的活动 |
| `perfectEvents` | 活动评分 | 平均评分、评分分布、0–100 归一化团体综合分排行，以及默认五条、可在卡片内展开的满分活动 |
| `cheki` | 拍立得 | 拍立得数、艺人数、月度分布、艺人占比与排行 |

自定义粒度固定为本表中的顶层 section。即使某些内部内容只在特定时间范围出现，也不单独成为配置项。

## 默认配置

首次使用、旧版本首次升级到支持统计自定义的版本，或偏好读取失败时，默认全部启用并保持当前页面顺序：

1. 活动
2. 活跃度
3. 单推
4. 支出
5. 活动评分
6. 拍立得

默认配置不得改变升级前用户看到的统计页面。

## 统计页展示规则

- 统计页按已保存的 section 数组顺序渲染，只展示 `visible: true` 的项。
- 同一套配置应用于周、月、年、自定义和全部时间；范围只改变统计数据，不改变 section 顺序或显隐。
- section 内部沿用现有条件展示，范围不适用时可以显示说明，但这不改变 section 自身的启用状态。
- 「活跃度」只在「年」口径加载并展示全年热力图。只有存在 `completed` 活动的日期会点亮：1 级表示仅有活动，2 级表示活动加 1–5 张拍立得，3 级表示活动加超过 5 张拍立得；只有拍立得而没有已完成活动的日期保持空白。周、月、自定义和全部时间显示切换年度的说明，不执行每日聚合查询。
- 没有设置单推时，如果「单推」已启用，继续展示现有引导空态；不得自动隐藏该 section。
- section 暂时没有数据时，继续使用该 section 的现有空态，不修改用户配置。
- 用户可以隐藏全部 section。此时保留页面标题和周期选择能力，并显示专用空态：
  - 标题：`未显示任何内容`
  - 描述：`在“统计自定义”中选择要显示的内容。`
  - 操作：`去编辑`
- 空态操作进入与其他入口相同的统计自定义页面。

## 统计时间范围

统计页标题下方使用 Expo SDK 57 的原生 `SegmentedControl` 提供 `周 / 月 / 年 / 自定义` 四个范围入口。当前周期在分段控件下方居中显示，左右两侧箭头切换相邻周期；中间日期文本独立居中，不显示额外下拉图标。点击中间值后，周进入日历选择器、月进入月份选择器、年进入年份选择器。点击「自定义」始终打开自由日期范围卡片，不得根据当前已生效的周、月或年沿用其选择器；「全部时间」作为该卡片内唯一的额外快捷操作。全部时间和自定义范围不启用前后箭头，并都保持「自定义」分段选中；即使从年切换到自定义后未输入日期并关闭，下一次点击中间日期仍打开自定义范围。时间范围控件属于页面内容，不吸顶；工具栏只保留统计模块「编辑」入口。

- App 冷启动且路由未携带合法时间范围时使用设置页「统计默认视图」配置的范围（未配置时默认本月），不把时间范围写入 AsyncStorage。
- 设置页提供「统计默认视图」选项（周 / 月 / 年），通过 AsyncStorage 持久化；只在冷启动且没有路由范围时生效，不改变本次运行期间已选范围。
- 同一次 App 运行期间，离开统计 Tab 再返回时保留当前范围；曾经选择过的自定义范围也在本次运行期间保留。从周、月或年点击「自定义」时，若已有最近一次自定义范围则直接应用，不再次弹出选择器；只有尚未选择过自定义日期时才弹出。第二行日期入口始终可重新编辑当前或最近的自定义范围。
- 显式路由参数优先于默认视图。快捷范围可使用范围类型表达，自定义范围使用 `startDate/endDate`，日期格式固定为 `YYYY-MM-DD`。
- 本周、本月和本年都是包含起止日的完整自然周期，可以包含今天之后的日期。本周的起始日跟随系统地区设置。
- 自定义范围包含起始日和结束日，允许单日、跨月、跨年以及未来日期，不限制跨度。
- 原生分段控件与周期导航组成同一个居中的页面级控件。周显示完整起止日期，例如 `2026/08/10 – 2026/08/16`；月显示 `2026 年 8 月`；年显示 `2026 年`；「全部时间」显示 `全部时间`。左右箭头触控目标不低于 44x44，辅助功能名称按口径分别使用「上一周 / 下一周」「上个月 / 下个月」「上一年 / 下一年」。
- 点击周、月或年后立即应用，并保持用户当前滚动位置；查询期间保留旧内容直至新结果就绪，避免页面塌缩跳动。自定义范围只在用户点击「应用」后生效；点击选择器内「全部时间」立即应用；关闭卡片不改变当前统计口径。
- 所选范围统一应用于全部可见 section。统计卡片下钻到活动或切册列表时必须携带同一范围，列表结果不得回退为年度或月份口径。

### 自定义范围选择器

复用项目已安装的 `react-native-calendars`，不自绘日历。使用约 66% 屏幕高度的 `BottomSheetDialog` 承载单月日历，由组件负责月份、日期格、翻页、范围色带、主题和本地化；用户可用左右箭头或横向滑动切换月份，也可在日历上方按 `YYYY-MM-DD` 手动输入起止日期，输入数字时自动补齐中横杠。范围色带只生成当前可见月份的标记，不能随自定义范围总跨度线性增长。

- 弹出卡片标题使用「选择日期范围」，字段使用「开始日期 / 结束日期」，主操作使用「应用」。
- 第一次点击设置开始日，第二次点击设置结束日。
- 第二次点击早于当前开始日时，将该日期重置为新的开始日并等待结束日；点击同一天得到单日范围。
- 手动输入必须校验实际存在的日期和起止顺序；格式无效或结束早于起始时显示行内错误并禁用确认。
- 首次打开时定位当前月；本次运行期间再次编辑时定位已有自定义范围的起始月。
- 日期选择器不提供选择整月、上一年、下一年或回到今天等额外快捷操作，只在标题区保留「全部时间」；范围摘要不在标题下方重复展示。
- 范围未完整时不可应用；关闭按钮、下滑关闭和 Android 返回键均视为取消，不改变当前统计范围。
- 弹出卡片必须支持浅色/深色主题、动态字体和不低于 44px 的触控目标；较矮屏幕允许卡片内容内部滚动，不扩展为全屏。

### 时间聚合与数据归属

- Repository 使用包含首尾的 `startDate <= date <= endDate` 查询；全部时间不增加日期条件。
- 活动继续按代表活动的首场日期归属，一个跨日活动不会因为多个场次落入范围而重复计数。
- 拍立得继续优先使用用户填写日期，缺失时使用创建时间。
- 趋势图按范围自适应分桶：不超过 31 天按日，不超过 366 天按月，更长范围按年；只展示与所选范围相交的桶。
- 密集日粒度趋势图缩窄柱体和间距，零值仅保留弱基线；周、月视图显示非零柱顶数值，标注保留可容纳三位数字的宽度；常规情况下只有当柱顶数字间距过近且数值相同时才省略重复数字，若密集数据仍会发生标注碰撞，则按可用间隔隐藏冲突标注。横轴标签优先显示有数据的日期并保持单行；年视图横轴固定展示 1–12 月，不省略月份。图表保持纯展示，不增加触摸选中交互。
- 自定义范围和完整自然周期都允许未来日期。尚无完成记录或消费数据的未来区间按正常空数据处理。

## 设置入口

统计自定义从统计页右上角的设置 icon 进入 `/settings/stats`；设置中心不再提供该入口。

平台规则：

- iOS 在统计页标题操作区提供设置 icon，使用原生 `Stack.Toolbar`。
- Android 在统计页标题操作区提供对应的设置 icon。
- 入口不显示新 section 红点。
- 设置页面使用路由 `/settings/stats`，页面标题为「统计自定义」。

## 设置页结构与交互

设置页复用首页功能卡片的排序交互：

1. 「显示」section。
2. 不可拖拽的分区线。
3. 「隐藏」section。

交互规则：

- 区内拖拽改变相对顺序。
- 拖过分区线同时改变顺序和显隐状态。
- 拖放完成后立即保存，不提供整页「保存」按钮。
- 页面提供「还原」操作，确认后还原默认顺序并显示所有统计内容；该操作不删除业务数据，使用普通强调色。
- 保存失败使用项目统一失败提示模式，并避免界面显示与持久化状态静默分叉。
- 每个条目只显示 section 名称，不显示 section 业务 icon，也不增加说明副文案。
- 条目右侧保留拖拽手柄；拖拽手柄属于操作控件，不视为业务 icon。
- 已隐藏条目沿用首页自定义的 muted 视觉表达。
- 浅色和深色模式都必须检查标题、分区状态、拖拽手柄和新 section 红点的可读性。

## 按需数据加载

统计页先读取并清洗偏好，再根据可见 section 计算本次需要的数据集合。加载规则不是简单地在现有完整查询之后过滤渲染。

- 隐藏 section 后，不执行仅由该 section 使用的查询。
- 同一数据被多个可见 section 使用时只查询一次；按所有可见 section 的依赖并集生成加载计划。
- 「支出」section 虽然会使用拍立得花费，但不依赖「拍立得」section 是否可见。只要「支出」可见，相应拍立得金额查询仍必须执行。
- 「单推」隐藏时，不执行单推活动、单推拍立得、最近单推活动和月度活跃等专属查询。
- 所有 section 隐藏时，不执行统计聚合查询，只加载偏好并展示专用空态。
- 多个 section 可见时，保持整页一次加载完成，等待本次依赖并集中的查询结束后统一展示，避免 section 陆续出现造成布局跳动。
- 周期变化、页面重新聚焦或配置变化后，按最新的可见 section 和周期重新生成加载计划。
- 异步结果不得用旧周期或旧配置覆盖新状态；实现时需要保留现有的失效请求保护或等效机制。

按需加载只优化查询范围，不改变任何统计口径。Repository 返回值、筛选规则和跳转参数仍遵守现有统计实现。

## 偏好与持久化

统计自定义属于本机 UI 偏好，使用独立 AsyncStorage key `ota-log.stats-preferences.v1`，不与首页偏好或数据库表混合。

建议模型：

```ts
type StatsSectionType =
  | 'activity'
  | 'activityHeatmap'
  | 'oshi'
  | 'spending'
  | 'perfectEvents'
  | 'cheki';

type StatsSectionConfig = {
  type: StatsSectionType;
  visible: boolean;
};

type StatsPreferences = {
  sections: StatsSectionConfig[];
  seenSectionTypes: StatsSectionType[];
};
```

数组顺序就是统计页展示顺序。读取和保存时必须清洗配置：

- 删除未知类型和重复项。
- 保留合法项的顺序与 `visible` 状态。
- 缺少当前已知类型时按「未来新增 section」规则补齐。
- 非法 JSON 或整体结构不可恢复时回退到完整默认配置。
- 从未保存过统计偏好的用户使用完整默认配置，并把当前所有 section 视为已知，不显示新 section 红点。

## 未来新增 section

新增 section 时必须区分「从未有过配置」与「已有旧配置但缺少新类型」：

- 从未保存过配置的新用户：使用新版完整默认布局；新增 section 可以按新版默认值启用。
- 已有配置的用户：将缺少的新 section 追加到未启用区末尾，默认 `visible: false`，不打乱已有顺序。
- 新增 section 在首次打开统计自定义页面时，在条目名称旁显示一个小红点。
- 红点只出现在统计自定义页面的具体新条目旁；统计页「编辑」按钮和「设置 > 外观」入口均不显示红点。
- 首次访问时红点在当前页面停留期间可见；页面完成展示后记录对应类型已查看，后续再次进入时不再显示。
- 用户不需要启用新 section 才能消除提示。
- 多个新 section 同时加入时，每个未查看条目分别显示红点，并在同一次访问后一起记为已查看。

`seenSectionTypes` 只服务于新 section 提示，不影响显隐和排序。实现可在首次加载页面时保留本次 `newSectionTypes` 用于渲染，同时持久化更新后的已查看集合，从而保证红点在首次访问中可见、下次访问消失。

## 兼容与错误处理

- 此功能不需要 SQLite migration。
- 统计偏好缺失时不得弹出错误，直接使用默认配置。
- 偏好读取失败或内容损坏时静默使用默认配置，不阻塞统计页进入。
- 保存失败时应提示用户；如选择回滚界面状态，必须恢复到最后一次成功保存的配置。
- 艺人或统计业务数据变化不得改写 section 偏好。
- 路由携带年份和月份进入统计页时，继续应用全局 section 配置。

## 验收标准

- 统计自定义页列出六个顶层 section，条目只有名称和拖拽手柄，没有业务 icon 或说明副文案。
- 用户可以在「显示」和「隐藏」分区内、跨分区拖拽，并在返回统计页后看到正确的显隐与顺序。
- 所有统计周期使用同一套布局。
- 默认配置与改版前的完整统计页一致。
- 还原后恢复默认顺序并显示所有统计内容。
- 隐藏全部 section 时显示专用空态，且可以从空态进入统计自定义。
- 统计页工具栏和「设置 > 外观」都能进入同一个统计自定义页面。
- 没有设置单推时，已启用的单推 section 显示引导空态。
- 隐藏 section 的专属 Repository 查询不会执行；共享数据在仍有可见消费者时继续正确加载。
- 所有 section 隐藏时不执行统计聚合查询。
- 未来新增 section 对已有配置默认关闭并追加到未启用区末尾。
- 新 section 红点只在统计自定义页面的对应条目旁首次显示，第二次进入时消失。
- 偏好损坏、未知类型、重复类型、缺失类型和保存失败都有可预期行为。
- 浅色和深色模式下，设置页、统计页及全部隐藏空态均可读且无溢出。

## 测试建议

- 为统计偏好工具增加纯函数和 AsyncStorage 单测，覆盖默认值、排序、显隐、坏 JSON、去重、未知类型、缺项补齐和保存清洗。
- 覆盖首次安装无红点、已有配置遇到新 section 默认关闭、首次访问显示红点、再次访问消失。
- 将统计数据加载计划抽成可测试逻辑，验证每种 section 组合对应的查询依赖，尤其是支出统计对拍立得金额的跨 section 依赖。
- 验证全部隐藏时不调用统计 Repository，并验证「活跃度」只在年度口径执行活动和拍立得每日聚合查询及三级映射。
- 验证周期切换和快速返回不会被旧异步结果覆盖。
- 手工验证 iOS 与 Android 的两个入口、拖拽跨分区、还原、全部隐藏空态，以及浅色/深色模式。

## 统计页面呈现

文件：`app/(tabs)/stats/index.tsx`

统计页用于回顾和比较，不只是展示数字。

顶层 section 的显示、隐藏、排序、设置入口、未来新增项提示和按需查询规则见 `docs/product/stats-customization.md`。

- 标题下方使用一个居中的时间范围控件：Expo 原生分段控件切换 `周 / 月 / 年 / 自定义`。下方周期导航两侧使用前后箭头，中间按周显示日期范围、按月显示 `YYYY 年 M 月`、按年显示 `YYYY 年`；日期文本在左右箭头之间独立居中，不显示额外下拉图标。点击中间值后，周进入日历、月进入月份选择器、年进入年份选择器。统一的 `StatsRangePicker` 根据本次点击显式传入的模式渲染对应选择器，不依赖当前已生效范围；自定义使用约 66% 屏幕高度的底部弹出卡片，标题为「选择日期范围」，支持自由选择开始和结束日期，日期输入自动补齐中横杠，并仅额外提供「全部时间」快捷操作。日期范围弹窗不重复展示顶部日期摘要，也不显示右上角关闭图标；控件随页面内容滚动且不吸顶；切换范围保持当前滚动位置和旧内容，待新统计结果就绪后原位更新。
- App 冷启动默认本月，不持久化时间范围；同一次运行期间保留当前范围和最近一次自定义范围。已经选择过自定义日期时，从周、月或年切回「自定义」直接恢复最近范围，不再次弹出选择器；点击第二行日期仍可重新编辑。显式路由范围优先于默认值。
- 本周跟随系统地区的周起始设置；本周、本月和本年均为完整自然周期。自定义范围首尾包含、允许未来日期且不限制跨度。
- 自定义范围使用 `react-native-calendars` 的单月日历，左右翻月或滑动切换月份，并提供 `YYYY-MM-DD` 开始和结束日期手动输入；无效日期或倒序范围显示行内错误且不可应用。日历范围标记只计算当前可见月份，避免超长范围拖慢选择器。点击「应用」后更新日期范围，选择「全部时间」立即应用，关闭卡片不改变当前范围。
- 趋势图按范围跨度自适应为日、月或年分桶；密集日粒度保留每天的数据柱，缩窄柱体和间距，零值仅保留弱基线。周、月视图显示非零柱顶数值，标注保留可容纳三位数字的宽度；常规情况下只有当柱顶数字间距过近且数值相同时才省略重复数字，若密集数据仍会发生标注碰撞，则按可用间隔隐藏冲突标注。横轴标签优先显示有数据的日期，标签保持单行。年视图横轴固定展示 1–12 月，不省略月份。图表保持纯展示，不增加触摸选中交互。活动按首场日期归属，拍立得继续使用填写日期并以创建时间兜底。
- 统计卡片下钻到活动或切册列表时继承相同时间范围。
- iOS 与 Android 的统计页右上角使用设置 icon（与电子切册「显示选项」一致），进入 `/settings/stats`；统计自定义不在设置中心提供入口。
- 统计文案保持短、具体且以结果为中心：所选时间使用「所选时间」表达，设置分区使用「显示 / 隐藏」，还原布局不使用 danger 语义。时间范围使用完整的「自定义」表达。
- 六个顶层 section 支持全局显隐和排序；隐藏项不执行专属统计查询，共享查询按所有可见 section 的依赖并集执行。
- Wide（窗口宽度 ≥ 960）保留顶层 section 的纵向排序，只在 section 内重排为仪表盘布局：活动趋势与地点摘要并排、艺人排行独占下一行；单推概览与最近活动并排；支出四个 KPI 同排；评分分布与团体排行并排；拍立得分布与艺人占比并排、艺人排行独占下一行。Compact / Regular 保持原有单列结构。周期控件始终横跨内容区，但仍随页面滚动且不吸顶。
- 趋势图按所在卡片的实际宽度计算标签碰撞，最大绘制宽度为 720；宽于该值时在卡片内居中，不继续拉宽柱体。年度活跃度热力图同样限制在 720 宽的居中内容区，窄窗口继续支持横向滚动。
- SectionHeader 使用 3x16 accent 竖线、17/700 标题、`lineHeight: 35`、可选 count badge 和右侧 action。
- StatBox 数字使用 28/900，compact 可降到 24。
- 统计页顶部摘要已移除，不再按所有时间、年度或月度展示摘要卡。
- 排行、支出、月度分布应优先解释口径，避免用户误解。
- 活动 section 内包含「艺人排行」卡片；它只统计显式设为团体且直接参与的已完成活动，使用 `ArtistRankingList` 展示，默认展示前十并可展开完整排行。
- 活跃度 section 使用 `react-native-chart-kit` v2 `ContributionGraph` 展示「年」口径的已完成活动与拍立得综合记录。只有存在已完成活动的日期会点亮：1 级为仅活动，2 级为活动加 1–5 张拍立得，3 级为活动加超过 5 张拍立得；只有拍立得的日期保持空白。支持横向滚动，轻点后显示当天活动场数与拍立得张数；未选择日期时不显示操作提示。周、月和自定义口径不加载每日聚合，只显示「选择“年”查看活跃度 / 仅支持年度视图」。
- 支出 section 使用「支出最高的活动」展示花费最高的五场活动，使用 `EventRow`，副文本为日期与门票/特典花费（日期段不加 icon），右侧为总花费，不显示进度条；行高 70 并垂直居中，保持易读和易点按。每一行保持对称的上下内边距，列表卡片不再额外叠加底部内边距，使最后一行在上一条分隔线与卡片底边之间保持居中。
- 活动评分 section 只统计已完成且填写评分的活动，展示平均评分、1–5 星分布、评分最高的团体和满分活动。团体排行只使用显式团体的直接出演，同一活动对同一团体只计一次；综合分归一化到 0–100，公式为 `100 ×（平均评分 ÷ 5）× √（该团体已评分场次 ÷ 榜内最多已评分场次）`，页面按整数综合分排序，并辅助展示原始平均分和已评分场次。满分活动标题、活动行和展开/收起操作位于同一卡片内，使用 `EventRow` + `ExpandableList`，默认展示五条；副文本为日期与地点（地点段带 `eventLocation` icon，城市与地点用「·」连接），右侧为评分，列表样式与支出排行一致；团体排行与满分活动列表的每一行保持对称上下内边距，列表卡片不额外叠加底部内边距，整数评分不强制显示小数位。
- 拍立得排行上方显示艺人占比环形图：前三位有效艺人分别成段，其余艺人及未关联记录合并为「其他」，中心显示当前范围总张数。艺人扇区使用加粗环宽突出主体，「其他」与底环保持较细环宽；占比仍由各段的角度表达。图例显示前三位头像，单推艺人复用 `OshiAvatar` 的渐变环和红色实心心形；对应扇区优先使用经过亮度、高饱和度与相似度校正的明亮头像主色，取色失败时回退并增强主题配色，「其他」始终使用中性色。排行继续使用 `ArtistRankingList`，默认展示前十并可展开完整排行；头像由 repository 提供的 `avatarUri` 渲染，并在张数后显示占当前范围总张数的百分比；进度条仍以第一名为满宽，保持排行比较语义。
- 单推 section 标题固定为「单推」，卡片内标题使用头像 + 名称，不再单独展示“参加活动 xx 次，拍了 xx 张”的摘要文案。
- 单推 section 的「最近一次活动」以独立 `EventCard` 展示（eyebrow + 隐藏状态 chip）；Compact / Regular 位于单推大卡下方，Wide 位于概览右侧；所选时间内无相关活动时显示空态卡片。
