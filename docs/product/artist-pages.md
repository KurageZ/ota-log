# 艺人管理与详情

页面细节由 UI/UX 总文档迁入；跨页面规则见 [UI/UX](ui-ux.md)，产品定位见 [PRODUCT.md](../../PRODUCT.md)，术语见 [CONTEXT.md](../../CONTEXT.md)。仅在相关任务改变这些行为时更新。

## 艺人管理


- 新建艺人默认不设置类型；类型未设置时新建页不提供所属关系选择，提示先设置类型后再记录；列表支持未设置、个人和团体筛选。
- 新建页艺人类型选择器按所选类型显示不同提示：不设置提示「设置类型后，可记录所属关系」；个人提示「可记录所属团体等信息，并自动关联到所属团体的活动」；团体提示「可记录所属成员等信息，并将团体活动关联到所属成员」。
- 新建页选择个人后显示「所属团体」多选控件（候选为团体类型艺人），选择团体后显示「成员」多选控件（候选为个人类型艺人）；卡片底部「高级」可展开履历编辑，为每条关系补充入团 / 最后在团日期（复用活动表单的日期输入：自动补横杠、失焦归一化、非法值红框并拦截保存），保存时生成正式履历。
- 艺人管理页首次展示一张可关闭的说明卡，解释设置类型会启用多团体履历与日期感知活动关联；关闭后不再展示，统计页不提供入口。
- 编辑页与新建页结构一致（基础信息 / 类型与关系 / 背景图），类型选择位于「类型与关系」卡片顶部，按所选类型显示与新建页相同的提示。
- 编辑页个人显示「所属团体」多选（候选为团体类型艺人），团体显示「成员」多选（候选为个人类型艺人）；选择器选中态展示全部履历（含历史所属，超出上限提供展开），仅含历史关系的 chip 点击可选择「重新加入」或「删除该艺人的关系」；卡片底部「高级」展开履历编辑，入团 / 最后在团日期复用活动表单日期输入（自动补横杠、失焦归一化、失焦或提交后标红并拦截保存），已存在履历时进入页面自动展开；履历每行提供删除操作，可选择「结束再团关系」（最后在团日期设为今天并保留历史）或「直接删除关系」（彻底移除），已结束的关系只提供直接删除。
- 已有正式履历或普通所属的记录禁止直接更改类型，需前往「设置 → 数据管理 → 艺人类型转换」整组转换；类型未设置且已有普通所属的记录保留维护入口并显示旧数据说明，没有普通所属的未设置记录不显示任何关系控件。
- 个人可同时拥有多个当前团体；基础摘要只显示当前所属，完整时间履历放在高级内容或详情信息中。
- 团体编辑页可选择当前个人成员；移除当前关系默认把最后在团日期设为今天并保留历史，再次加入生成新的一段。
- 新建和编辑页的正式所属选择器会利用当前艺人名称与简称双向推荐关系候选：个人名称中包含团体名称或有效片段时优先推荐该团体，团体名称与个人名称存在同类匹配时也优先推荐该个人；推荐只改变空搜索状态下的候选顺序并展示命中依据，不自动选择。
- 类型未设置的记录继续使用无日期普通所属；它与个人或团体不能建立所属关系，也不触发活动、单推、收藏和统计的间接命中。
- 批量类型转换只处理未设置记录。页面顶部以说明卡片解释整理流程，样式对齐备份页使用说明（MenuCard + 图标标题），内容分点阐述且不含排序说明：整组转换规则、单独艺人选择、最后确认清单。列表不设常驻「已选择」区，勾选后卡片原位保留并高亮，完整审查放在最后一步的「确认转换」弹窗：弹窗汇总人数 / 团体数 / 关系数，列出全部已选组（含展开的成员与转换结果），并提示转换后果（普通所属变正式履历、类型不可直接再改）。未选择内容分为「已有所属关系」与「单独艺人」两个分区，分区标题带数量；「已有所属关系」分区提供「全选 / 取消全选」，副文案为「已有所属关系的艺人仅能整组转换」。关系卡片由团体主行与可展开成员区组成：团体主行承载整组勾选、活动场数与展开箭头；成员区默认收起为一行头像（最多 6 个，超出以 +N 计数；缺头像显示名字首字），点击可展开为成员列表，勾选整组后自动展开。单独艺人没有整组语义，勾选后默认设为个人，可在右侧改为团体；分区提供「全选为个人 / 全选为团体」两个批量按钮。搜索位于列表顶部，按团体或成员过滤两个分区。关系组及组内艺人都按直接关联活动数量优先展示，并显示活动场数。多层结构因中间节点角色冲突而整组禁用、常驻展开并提示先整理所属。用户检查后再统一确认转换。

### 艺人详情背景图模式

- 艺人详情页不使用 iOS 大标题承载名称，名称始终绘制在页面内：无背景图模式居中显示在头像下方，背景图模式位于 Hero 底部左侧、紧凑元信息上方。iOS 返回键由 Native Stack 自动提供，编辑入口通过原生 `Stack.Toolbar` 呈现，不重复绘制页面内顶部返回/编辑控件。
- 背景图使用 edge-to-edge Hero，竖屏首屏高度约为可视高度的 70%，并限制在屏幕宽度的 1.6 倍以内以兼顾宽屏。艺人名称和紧凑元信息放在图片底部左侧；背景图已经承担身份表达时，不重复展示中央头像。
- iOS 的「活动 / 拍立得」切换复用统计页同款 Expo 原生 `SegmentedControl`，并根据普通页面主题或背景图明暗设置 appearance；Android 保留有边框的主题分段控件。背景图模式下 iOS 原生 header 透明并叠加在 Hero 上，返回与编辑不再使用 Liquid Glass 控件。Liquid Glass 不用于月份标题、EventCard 或其他内容卡片。
- 「活动 / 拍立得」分段控件固定在完整背景图底部，左右保留 16px、底部保留 10px；扩展出的约 96px 区域属于同一张图片，并渐变到图片派生底色，控件下方直接进入实体活动列表或拍立得网格，不额外预留一整段空白。过渡区不得重新渲染或重新裁切第二张背景图。切换时两类内容保持挂载，仅切换可见层，避免 Hero、背景图和玻璃控件重建闪烁。
- Hero 滚出后的名称处理按平台区分：Android 名称进入自绘紧凑导航栏，iOS 名称始终在页面内并随 Hero 一起滚出，原生 header 不显示艺人名。分段控件保留在 Hero 底部并随内容一起滚出，不吸附到导航栏下方。切换内容时保留各自滚动位置，用户回到页面顶部后再切换活动和拍立得。
- 单推、收藏、所属和链接以无背景的紧凑媒体操作呈现，不堆叠多个大胶囊。
- 图片提取色只作为低饱和环境色混入页面底色。深色背景保持近黑基底，卡片使用低对比度的浅色透明层，避免形成黑色卡片墙。
- 背景图模式的活动列表继续复用 `buildEventMonthSections` 和 `EventCard`；月份标题切换为无 accent 竖线、无数字 badge 的媒体式标题，普通艺人详情和所有活动页保持现有 section 样式。
