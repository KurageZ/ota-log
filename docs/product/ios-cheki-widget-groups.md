# iOS 拍立得分组小组件设计

> 状态：主体实现已落地，仍需完成已知评审问题修复与 iOS 真机验收。
>
> 本文是长期设计事实与验收依据；实现进度以 `docs/progress/now.md` 为准。

## 1. 背景与目标

当前「拍立得回忆」小组件只有一份全局艺人筛选和一条共享 timeline。用户在桌面添加多个同类小组件时，所有实例会展示相同内容。

本次优化的目标是：

- 提供 6 个固定的拍立得分组槽位。
- 每个桌面小组件实例可在系统编辑界面选择一个槽位。
- 不同槽位拥有独立的集合定义和轮播状态。
- 同一槽位的多个实例保持同步。
- 分组既支持手动策展，也支持规则驱动的自动集合。
- 分组属于用户数据，进入 SQLite 和完整备份。

不在本次范围内：

- iOS 16 兼容。
- 动态增删系统选择器里的槽位。
- 在系统选择器中展示 App 内自定义的组名。
- 小组件内的「下一张」按钮。
- 背签图片展示。
- Android 小组件。

## 2. 平台与实例配置

- iOS 最低系统版本提升到 iOS 17。
- 保留一个 `ChekiPhotoWidget` Widget kind，不为 6 个槽位注册 6 个重复 Widget。
- 通过 `expo-widgets` 的 `ios.configuration` 声明枚举参数 `slot`。
- 系统选择器固定显示「分组 1」至「分组 6」，内部值使用稳定的 `group1` 至 `group6`。
- 新增实例默认选择分组 1。
- App 内允许为槽位改名，但自定义名称不会同步到系统选择器；设置页必须明确提示编号映射。
- 同一槽位的多个 Widget 实例共享集合、轮播锚点和半小时更新时间；小号与中号按各自步幅取图。用户需要不同内容时，应选择不同槽位。

槽位数量与身份是稳定产品约束。槽位不可新增、删除或重排；「重置分组」是固定槽位对应的删除语义。

## 3. 分组模型

每个槽位由稳定编号、用户名称、一个集合来源和轮播状态组成。集合来源是互斥联合：

```ts
type ChekiWidgetGroupSource =
  | {
      type: 'manual';
      chekiItemIds: string[];
    }
  | {
      type: 'filter';
      rules: ChekiWidgetFilterRules;
    };

interface ChekiWidgetGroup {
  slot: 1 | 2 | 3 | 4 | 5 | 6;
  name: string;
  source: ChekiWidgetGroupSource | null;
  rotationAnchorAt: string | null;
}
```

不变量：

- 名称非空、去除首尾空白后最多 20 个字符、6 个名称不可重复。
- `source === null` 表示未配置。
- 手动集合与自动筛选不会同时保存。
- 切换来源前必须确认；切换会清除旧集合定义，但保留名称。
- 重置会清空集合、清空轮播状态，并把名称恢复为「分组 N」。
- 不迁移旧版全局艺人筛选，功能升级后 6 个槽位均从未配置开始。

## 4. 手动集合

手动集合保存有序的拍立得 item ID：

- 最多 48 张。
- 首次保存时至少有 1 张当前可展示的正面图片。
- 新选择的照片默认追加到末尾。
- 用户可在相册模式「中」密度的响应式网格中长按拖动排序。
- 拖动之外提供可访问的「前移」「后移」操作。
- 整条拍立得 item 被删除时，成员关系随之删除。
- 只移除正面图片时，成员关系保留但进入休眠；重新添加正面后自动恢复展示。
- 已有分组后来全部进入休眠时，允许继续修改名称并保存，不强制删除用户的策展关系。

手动选图使用与拍立得贴纸相机共用的 `ChekiPickerScreen`：只列出有正面照片的项目，以电子切册「小」密度相册网格多选，并接入相册模式的完整关键词搜索与日期、艺人、规格、关联活动、备注、收藏、背签筛选。搜索或筛选不清除已选内容，也不改变点选顺序；不另做低信息密度的纯文本列表。

## 5. 自动筛选

自动集合保存规则，不保存一次性解析后的 ID 列表。App 内数据变化时重新解析规则，因此内容会自动更新。

### 5.1 支持条件

- 艺人：多选，只匹配拍立得记录直接关联的艺人，不展开团体成员。
- 活动：多选。
- 收藏：`仅收藏` 开关。
- 日期：本月、今年、自定义起止日期。
- 拍立得规格：多选。

日期首尾均包含。没有填写拍摄日期时，使用记录创建日期，保持与电子切册及统计模块的 `COALESCE(date, created_at)` 语义一致。

### 5.2 组合规则

- 同一类别内使用 OR，例如「艺人 A 或艺人 B」。
- 不同类别间使用 AND，例如「(艺人 A 或 B) 且 已收藏 且 今年」。
- 至少设置一个条件。
- 首次保存时当前至少匹配 1 张可展示的正面图片。
- 保存成功后，未来因删除、取消收藏或日期变化变为 0 张时保留规则，显示「暂无符合条件的拍立得」。
- 删除规则引用的艺人或活动时，移除失效引用；如果所有条件因此消失，槽位退回未配置。
- 自动集合按有效日期从新到旧排序，只展示最新 48 张；相同日期使用现有 Repository 的稳定排序规则。

## 6. 正面图片与可展示资格

Widget 只展示 `front` 图片：

- 不展示背签。
- 没有正面时不回退背签。
- 自动筛选只把有正面的 item 计入匹配结果。
- 手动集合可以保留失去正面的休眠成员，但休眠成员不计入概览页数量，也不进入 timeline。
- 单张正面损坏或缩略图生成失败时跳过该张；全部失败时显示无可展示内容，并在下次同步重试。

## 7. 轮播语义

- 每 30 分钟整点或半点切换一次，前台同步不得改变下一次切换边界。
- 每次生成未来 48 个 entry，覆盖 24 小时。
- 小号显示当前 1 张，每次向前推进 1 张。
- 中号把当前张放在中间，两侧显示接下来 2 张，每次整组三张向前推进 3 张，确保同一时刻更新三张；不足 3 张时按实际数量居中，不制造空占位，也不重复补齐第三张。
- 只有 1 张时自然保持固定展示。
- 每个槽位保存独立的轮播锚点。
- 普通冷启动或回到前台只续接进度，不回到第一张。
- 集合成员或顺序改变时重置锚点：手动集合从第一张开始，自动集合从最新一张开始。
- 是否重置应根据最终可展示 item ID 的有序指纹判断；仅打开 App、缩略图重建或无关字段变化不得重置。

同一 Widget kind 的原生 timeline 仍然共享。每个 entry 应携带 6 个槽位各自的展示帧，Widget 视图根据 `environment.configuration.slot` 选择当前实例需要的槽位。不要尝试调用 6 次 `updateTimeline()`；后一次会覆盖前一次。

## 8. 点击、空态与视觉

### 8.1 点击行为

- 有内容时，点击整个 Widget 打开电子切册首页 `/cheki`。
- 不支持点击某张图片直接打开详情。
- 不提供「下一张」按钮。
- 未配置或当前无内容时，点击进入对应槽位编辑页。

空态深链需要包含槽位编号；Widget URL 必须根据实例配置生成。

### 8.2 空态文案

至少区分：

- 「尚未配置分组」：`source === null`。
- 「暂无符合条件的拍立得」：自动规则有效，但解析结果为空。
- 「暂无可展示的拍立得」：手动成员均休眠，或所有缩略图处理失败。

### 8.3 视觉

- 保留暖米色背景；小号和中号都按源图片比例完整显示。中号使用 1–3 个等宽槽位，图片在槽位内居中适配并允许留白。
- 不在图片上叠加分组名称。
- 图片使用 full-color accented rendering，继续检查 iOS Home Screen tinting。
- 浅色、深色都保持同一暖米色相册质感。

## 9. 设置界面

`/settings/widget` 改为 6 个槽位的概览页：

- 每行显示固定编号、自定义名称、来源模式和最终可展示数量。
- 数量只显示当前真正可进入 Widget 的照片数，不显示规则原始匹配总数，也不单列休眠数量。
- 点击进入独立槽位编辑页。
- 提供重置操作并二次确认。

槽位编辑页：

- 使用明确的「保存」按钮。
- 所有修改先进入页面草稿。
- 带未保存修改返回时询问是否放弃。
- 切换手动/筛选来源时，如果原来源已有内容，先确认再清除。
- 页面信息顺序固定为「分组名称 / 内容来源 / 来源配置 / 当前内容」；名称输入框必须保留字段标签，手动与筛选模式使用带业务 icon 的大模式按钮。
- 手动模式使用标准菜单操作行「管理拍立得」进入多选；当前内容即为轮播顺序，不再常驻显示排序说明。首次有至少 2 张照片时显示一次性拖动教学提示，用户确认或开始拖动后永久隐藏。
- 自动模式使用标准菜单操作行「编辑筛选条件」，副文案摘要当前条件并显示条件类别数；筛选面板内的修改仅为临时草稿，点击「应用」后才更新槽位编辑页。
- 两种模式的用途说明紧跟内容来源模式按钮，并随当前选择切换；自动模式说明内容会随所选条件自动更新且最多展示 48 张。
- 自动模式直接在当前页面展示完整结果，不再截断为预览或提供「查看全部」子页面；结果网格使用与手动模式相同的「中」密度和图片尺寸，并与小组件使用同一套排序和最新 48 张上限，同时明确区分未设置条件、加载中、无匹配和有内容状态。
- 自动模式的艺人选择必须向共享 `ArtistSearchPicker` 传入当前单推艺人和完整艺人库，使单推艺人稳定排在候选首位，并继续使用个人类型优先的共享排序规范。
- 手动模式在槽位编辑页内提供相册多选、移除、相册模式「中」密度的响应式拖动排序和辅助排序操作，不另开排序子页面；排序网格直接位于页面内容流中，不使用卡片容器。
- 多选页顶部使用 App 标准导航操作：iOS 使用原生「取消 / 完成」Toolbar，Android 使用 Stack Header；已选数量在页面内容中展示。
- 小组件手动多选页把已选数量、当前结果数量和「全选 / 取消全选」合并在单行选择工具栏内，不允许换行；批量操作使用无独立底色的文字按钮和细分隔线。有搜索或筛选时文案改为「全选当前 / 取消当前」，只作用于当前结果，结果之外此前选中的项目保持不变；没有搜索或筛选时作用于全部候选。全选超过剩余名额时按当前结果顺序取前面的项目，最终最多 48 张。贴纸相机复用选择器但不显示该批量操作。

拖动排序使用项目现有 `react-native-reanimated-dnd`：

- 使用 `SortableGrid`/`SortableGridItem`。
- `onMove` 只处理触觉反馈，不同步写 React 外部数组。
- `onDrop` 根据 `allPositions` 生成草稿顺序。
- 添加或移除照片后重新挂载排序网格，避免库的内部排序状态与外部数据不同步。
- 只有点击保存后才写入 SQLite 和刷新 Widget。

## 10. 数据所有权与备份

分组是用户策展数据，不是本机 UI 偏好：

- 使用 SQLite 持久化，不再扩展现有 `chekiPhotoWidgetPreferences` AsyncStorage 格式。
- 纳入完整备份的数据和媒体一致性流程。
- 恢复完整备份时，备份中的分组完全覆盖本机分组。
- 旧版备份没有分组数据时，恢复为 6 个未配置槽位。
- 恢复完成后立即重新生成拍立得 Widget timeline。
- 桌面布局和系统中每个 Widget 实例选择的槽位属于 iOS 系统状态，不在 App 备份范围；恢复后已存在的实例仍按自己的槽位配置读取新数据。

## 11. 模块与 seam

实现应把规则解析、约束、轮播锚点和数据库细节集中在一个深模块中。页面、同步器和测试只通过该模块的 interface 工作，不直接拼 SQL 或重复筛选规则。

建议模块职责：

- 持久化 6 个槽位及其关联条件。
- 校验名称、来源、数量上限和首次保存条件。
- 解析手动/自动集合并返回最终有序、可展示的正面图片。
- 清理失效艺人/活动引用。
- 比较集合指纹并维护轮播锚点。
- 发出分组变化通知。

Widget 同步器负责 App Group 文件和 `expo-widgets` 更新，但不拥有业务规则。timeline 组合尽量保持为纯函数，输入 6 个已解析集合，输出 48 个共享 entry，作为主要测试 seam。

## 12. 同步触发与一致性

以下事件触发同步：

- App 初始化完成。
- App 回到前台。
- 拍立得新增、编辑、删除、收藏或正面图片变化。
- 分组保存或重置。
- 完整备份恢复完成。

同步继续使用串行合并策略：同步进行中收到新请求时只标记再执行一次，避免并发缩略图写入和 timeline 覆盖。

缩略图要求：

- 只缓存最终可展示集合的并集，同一拍立得跨分组去重。
- 文件身份必须能识别正面 URI 更新，不能只用稳定 item ID 导致旧缩略图永久复用。
- 清理不再被任何槽位使用的旧缩略图。
- 单张失败不阻断其他分组。

## 13. 验收标准

1. 添加 6 个小组件并分别选择 6 个槽位时，各自展示正确集合。
2. 两个实例选择同一槽位时共享轮播锚点并在相同半小时边界更新；小号逐张推进，中号整组三张推进。
3. 普通前台同步不重置；集合改变后从新集合第一张开始。
4. 自动规则遵守同类 OR、跨类 AND、正面限定和最新 48 张上限。
5. 手动拖动顺序与小组件轮播顺序一致。
6. 失去正面的手动成员休眠，恢复正面后重新出现。
7. 删除艺人或活动后规则引用被清理，无条件时槽位回到未配置。
8. 完整备份可往返保留槽位；旧备份恢复为未配置槽位。
9. 空态点击到正确槽位，有内容点击到电子切册首页。
10. 小号、中号、浅色、深色和 tinting 模式均无裁切、溢出或不可读状态。

## 14. 已知平台约束

- `expo-widgets` 可配置参数需要 iOS 17+，配置插件变化必须通过新的原生构建发布，不能仅靠 OTA。
- 系统选择器的 6 个枚举名称在构建时生成，不能动态读取 App 内自定义名称。
- `WidgetCenter.reloadTimelines(ofKind:)` 刷新同一 kind 的所有实例，因此槽位是共享状态身份，而不是 Widget 实例 ID。
- 从静态 Widget 升级为可配置 Widget 后，既有桌面实例是否自动采用默认分组 1 必须通过真机升级路径验证，并在发布说明中记录实际行为。
