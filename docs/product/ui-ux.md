# ota_log 产品设计文档

> 当前文档面向 `ota-log` 的 app 产品设计与实现维护。它记录当前代码中的设计事实、可复用模式和后续 UI 改动的验收标准。
>
> 最近校准日期：2026-07-01
> 当前 app 版本：1.4.2

---

## 文档定位

`design.md` 不是静态设计稿，也不是单纯 token 表。每次调整页面结构、共享组件、主题 token、重要文案或导航入口时，都应同步更新本文档。

本文档优先回答四类问题：

1. 产品要服务什么使用场景。
2. 页面和导航的当前结构是什么。
3. 新 UI 应复用哪些 token、组件和交互模式。
4. 设计变更完成前应该检查什么。

外部调研结论：

- 设计文档需要把「设计决策」抽象成可复用 token，而不是依赖具体色值。Atlassian 将 design tokens 定义为命名并存储设计决策的单一事实来源，并强调按语义选择 token，而不是按相似色值选择。参考：[Atlassian Design Tokens](https://atlassian.design/foundations/tokens/design-tokens/)。
- 颜色需要有层级和角色。Carbon 将背景、层级、文本、边框、状态、焦点等拆成角色 token，并要求 token 在不同主题中保持同一语义。参考：[Carbon Color](https://carbondesignsystem.com/elements/color/overview/)。
- 产品内文案也属于设计系统。Carbon 的内容指南强调清晰、逻辑、可翻译，并区分 onboarding、错误、表单标签等不同语境。参考：[Carbon Content](https://carbondesignsystem.com/guidelines/content/overview/)。
- 可访问性不能只靠颜色。WCAG 2.2 AA 要求普通文本与背景至少 4.5:1，大文本至少 3:1。参考：[WCAG Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。

因此，本文档按「产品原则 -> 信息架构 -> 基础 token -> 共享组件 -> 页面规范 -> 交互与验收」组织。

## 产品原则

ota_log 是本地优先的演出记录 app，主要服务日系和国内偶像、团体活动爱好者。用户打开 app 时通常要完成明确任务：查看下一场活动、补记录、查拍立得、看统计、整理艺人和备份数据。

设计方向：

- **任务优先**：首页直接呈现下一场活动和关键记录入口，不做营销式欢迎页。
- **本地记录感**：界面要像可靠的私人日志，允许密集信息，但保持扫描效率。
- **单推有情绪价值**：单推相关视觉可以更鲜明，使用渐变环、红色心形和置顶排序，但不要把所有页面染成单推色。
- **数据可回溯**：筛选、统计、拍立得聚合要让用户理解数据口径，避免只给漂亮数字。
- **一致性大于装饰**：标准控件、菜单行、筛选、卡片应复用同一套形态。新增页面优先使用已有共享组件。

## 信息架构

### 底部导航

当前底部导航按平台实现：iOS 使用 Expo Router `NativeTabs`，采用系统 Liquid Glass tab bar 和滚动最小化行为；Android 保留五个等宽悬浮胶囊 tab。两端入口和业务语义一致：

- 首页：`app/(tabs)/(home)/index.tsx`
- 日历：`app/(tabs)/calendar/index.tsx`
- 切册：`app/(tabs)/cheki/index.tsx`，页面标题保留「电子切册」
- 统计：`app/(tabs)/stats/index.tsx`
- 我的：`app/(tabs)/profile/index.tsx`

新建活动不放在底部导航常驻入口，改由首页右上角和所有活动页右上角进入 `/events/compose`。

### 我的页 IA

`Profile` 是身份和常用入口页，不承载复杂设置表单。当前结构：

1. 身份卡：头像、昵称、编辑入口、活动/完成/收藏/拍立得统计。
2. 单推：已设置时进入艺人详情，未设置时进入 `/settings/oshi`。
3. 功能：所有活动、艺人管理、重要日期。
4. 更多：设置、工具箱、关于。

Profile 上不直接放备份、清理、微博登录、主题、日历默认视图等操作。

我的页右上角提供齿轮设置 icon，点击进入 `/settings`，与「更多 → 设置」菜单入口一致。

### 设置页 IA

`/settings` 是单页设置中心。当前分组：

1. **个人**：个人资料、单推设置。
2. **偏好**：外观（子页，含显示模式与主题色）、功能（子页，含切册/统计默认视图与出演者确认）、日历（子页，周起始日与月视图展示）、首页自定义、统计自定义（子页）。
3. **小组件**（仅 iOS）：拍立得回忆的展示艺人设置。
4. **数据管理**：存储空间（含清理未使用图片）、备份和恢复（子页，含生成备份数据、保存到本地、恢复备份）、艺人类型转换。
5. **高级**（仅 dev）：移除孤立艺人、清空所有数据。正式包不显示该分组。

设置页以分组承载入口，避免单页过长：外观（`/settings/appearance`，显示模式与主题色合并）、功能（`/settings/features`，默认视图与出演者确认合并）与日历（`/settings/calendar`，周起始日与月视图展示）作为独立子页，入口均显示静态副文案、不显示当前值，点击进入查看。子页内每个功能一个 section，选项直接展示为单选卡片，不做折叠展开。仅备份三件套保留状态语义色（导出蓝 / 保存绿 / 恢复橙）。

设置页不使用大标题（`headerLargeTitle`），与 Tab 层级保持一致即可。

### 工具箱

`/tools` 承载低频但独立的工具入口。当前包含微博关注导入、登录微博、Chekiroku 数据导入、Ultima stamp planner，以及 iOS「拍立得贴纸相机」Demo。登录微博作为微博抓取的前置状态，放在「艺人导入」分组内，与微博关注导入相邻。新增工具时优先放这里，不要塞回 Profile。

拍立得贴纸相机当前仅支持 iOS，使用 App 内电子切册的正面照片作为贴纸来源，不请求系统相册读取权限。选择器直接复用电子切册的相册模式图片展示（按切册页「小」密度、统一比例呈现，网格宽度随屏幕自适应），标题与操作行避开状态栏安全区；支持最多 9 张多选并用数字标记点选顺序；达到上限后未选项目置灰。顶部提供「无优先 / 单推优先 / 收藏优先」三种互斥排序，优先项与普通项内部均保持时间倒序，切换排序不得改变已选内容和顺序；未设置单推时禁用对应选项。

贴纸不支持移动、缩放或手势旋转。单张固定在画面左下；多张以画面底部中央为圆心形成扇形，张角按画布宽度自适应、尽量让扇形铺满整个画面宽度（两张时向中间靠拢），拍立得中心连线沿圆弧排列（中间最高、两侧对称下沉），第一张位于左后方、最后一张位于右前方。每层贴纸都使用阴影，预览和最终 Skia 合成必须共用同一布局结果。相机页的「更换贴纸」重新打开选择器并保留当前选择，只有再次确认后才整组替换；结果页以「添加 App 水印」开关替代分辨率展示，默认开启、可关闭，开启后在图片中间最下方合成半透明 App 水印（预览与保存共用同一张图），并保留保存/分享与底部「重新拍摄」。

## 主题系统

主题偏好由 `useThemePreferences()` 持久化，实际取值通过 `useAppTheme()` 使用。

```ts
type AppThemeId = 'monoChrome' | 'classicViolet' | 'nightNeon';
type AppAppearance = 'system' | 'light' | 'dark';
type AppCalendarWeekStart = 'sunday' | 'monday';
```

默认值：

```ts
DEFAULT_THEME_ID = 'monoChrome';
DEFAULT_APPEARANCE = 'system';
DEFAULT_CALENDAR_WEEK_START = 'sunday';
```

主题标签：

| ID | UI 标签 | 用途 |
|----|---------|------|
| `monoChrome` | 极简 | 默认主题，低色彩背景配合多彩入口 icon |
| `classicViolet` | 紫色 | 品牌主题 |
| `nightNeon` | 粉色 | 更强情绪色主题 |

使用规则：

- 新代码取色必须优先走 `colors.xxx`、`theme.status[status]` 或明确的共享 helper。
- 不要按视觉相近随便拿 token。按用途取：文本用 `text/textSecondary/textMuted`，边框用 `divider/inputBorder`，主操作用 `accent/onAccent`。
- 角色 tint 可以存在，例如 `featureEvents/featureArtists/featureCheki`，但应进入 theme token。页面内临时硬编码只适合迁移期或明确的一次性品牌色。
- Profile、Settings、Tools 的菜单入口 icon tint 使用 `profileMenu`、`settingsMenu`、`toolsMenu`。极简主题允许这些入口保持多彩，用于提升入口识别度；不要在页面内直接写菜单色值。
- 深色模式不能用结构 token 当文本色。文本优先使用 `colors.text` 或 `colors.textSecondary`。

## 字体与排版

使用系统字体，不引入自定义字体文件。中文环境以 iOS/Android 系统 sans 为准。

| 用途 | Size | Weight | 说明 |
|------|------|--------|------|
| 页面标题 | 24-26 | 800-900 | 日历、统计、艺人管理等 |
| 详情页主标题 | 20-24 | 800-900 | 活动详情、艺人详情 |
| 卡片标题 | 16 | 700-800 | EventCard、首页卡片 |
| 列表标题 | 14-15 | 600-800 | 菜单、排行、列表 |
| 正文 | 14 | 400-500 | 备注、说明，`lineHeight` 约 20-22 |
| 次级信息 | 12.5-13 | 400-600 | 日期、地点、副标题 |
| 三级信息 | 11-12 | 400-600 | 空态辅助、标签说明 |

规则：

- 产品 UI 不使用 display 字体。

- 不随视口宽度动态缩放字号。窄屏通过换行、截断和 `adjustsFontSizeToFit` 局部兜底。

## 日期显示

App 内日期 / 月份显示统一使用横杠分隔的 ISO 风格短格式：

- 月份：`YYYY-MM`，例如 `2026-08`。
- 完整日期：`YYYY-MM-DD`，例如 `2026-08-14`。

列表月份 section 标题等日期分组标题必须使用该格式，不使用「2026年8月」等中文年月写法；存储格式即显示格式，不需要二次本地化。

例外（口语化业务文案，不适用本规范）：含星期或相对表达的日期（如「2026年8月14日 周五」「8月15日 周三」「今天」「周三」）、统计周期导航文案（如「2026 年 8 月」「2026/08/10 – 2026/08/16」）、表单输入占位符提示。

### 阴影

- 通用卡：`shadowOffset: { width: 0, height: 4 }`，`shadowOpacity` 约 0.08-0.2，`shadowRadius` 14，`elevation` 3。
- 菜单卡：`shadowOffset: { width: 0, height: 2 }`，`shadowOpacity` 0.06，`shadowRadius` 8，`elevation` 2。
- 首页卡片：边框用 `divider`，阴影更轻，避免整页像卡片墙。
- 首页置顶信息 / HomeUpcomingHero：`shadowOffset: { width: 0, height: 8 }`，亮色 `opacity 0.12`，暗色 `0.26`。
- Android floating tab bar 使用 `boxShadow`，亮色 `0 12px 26px rgba(31,18,53,0.12)`，暗色 `0 14px 34px rgba(0,0,0,0.36)`；iOS NativeTabs 的材质和阴影交给系统管理。

- 4px 基础网格。
- 页面左右 gutter：16px。
- 卡片内边距：14-16px。
- 卡片间距：10-12px。
- Section 间距：16-24px，Profile 上常用 20px。
- 触控目标：主要可点区域不低于 44x44。

## 共享组件

### 页面层级：Section / 卡片 / 字段

ota_log 大量采用卡片式布局，页面层级统一按「section -> 卡片 -> 字段」理解。

Section 是页面级分组。Section 标题放在卡片外，左侧使用 3x16 accent 竖条。页面级列表 / 日历分组（活动月份、电子切册记录月份、日历当天详情模块）统一使用 `EventSectionHeader`：标题 17/800 accent 色 + 计数胶囊（accentSoft 底、11/700）；表单与设置菜单分组使用 `SectionLabel` / `FormSectionLabel`（17/500 heading 色）。一个 section 内可以包含一个或多个卡片。

卡片是内容容器。卡片标题和描述语都是可选的：统计卡、排行卡、独立信息块等需要解释口径或内容时，可以在卡片内部使用加粗标题和辅助描述；普通表单字段组不需要卡片标题，因为 section 已经说明上下文。

字段是单个输入框、选择器、开关、日期、价格等控件。字段名是字段标签，不是标题。一组相关字段应该共用同一个卡片，例如「基础信息」下的「标题 / 日期 / 备注」；不要把同一组普通字段裸露在页面背景上，也不要把每个字段都拆成单独卡片。

例外：如果 section 内本身是一组可点击选项卡、菜单行、设置行、开关列表或独立卡片列表，它们已经是卡片 / 列表形态，不再额外包一层，避免卡片套卡片。

### SettingsMenu

文件：`src/components/SettingsMenu.tsx`

包含 `SectionLabel`、`MenuCard`、`MenuItem`、`SettingsChoiceCard`、`MenuRowSeparator`。

`SectionLabel` 规范：

- 容器横向排列，左侧为 3x16 accent 竖条，圆角 999。
- 标题文字 17/500，`lineHeight: 35`，颜色使用 `colors.heading`。
- 不使用 uppercase 或额外字间距。

页面级列表 / 月份分组标题不使用本节样式，统一改用 `EventSectionHeader`（17/800 accent + 计数胶囊，见上方「页面层级」说明）。

`MenuItem` 规范：

- 左侧图标容器 34x34，圆角 10，背景 `${tint}22`。
- icon 18px。
- label 15/500。
- subtitle 12，最多 2 行。
- badge 使用 `${tint}20` 背景，12/700。
- trailing icon 固定 `chevron-forward` 16px。
- `activeOpacity` 0.6。

用于 Profile、Settings、About、Tools 等导航式列表。新设置入口优先复用它。

`SettingsChoiceCard` 规范：

- 独立单选页的选项卡片：每行 label 15/500 + 可选描述（12，`lineHeight` 17）+ trailing radio。
- 单选选中项使用 `radio selected`（accent 实心 + 白点），`pending` 时显示 spinner 并禁用。
- 支持可选 `leadingColorOf` 在 label 前展示色点（如主题色选项）。
- 行间分隔使用 `MenuRowSeparator`（`leadingInset` 16）。
- 用于外观、功能等子页内的直选单选，不折叠。

`MenuRowSeparator` 规范：

- 行分隔线使用 `divider`，高度 `hairlineWidth`。
- 左侧 `marginLeft: 62`，与文字起始位置平齐（跳过 16 padding + 34 icon + 12 间距）；右侧 `marginRight: 16`，不触达卡片边界。
- 通过可选 `leadingInset` 调整左侧缩进；无 icon 的独立单选页（如 `/settings/appearance`、`/settings/features`）传 16。
- `MenuItem` 与 `SettingsChoiceCard` 的行间分隔统一使用该组件。

### AnimatedPressable

文件：`src/components/AnimatedPressable.tsx`

用于首页未来活动时间线等低数量卡片的轻量按压反馈。

- 使用 Reanimated，不使用 React Native `Animated`。
- 默认按压态：`scale 0.97`，`opacity 0.76`。
- 按下 70ms，松开 120ms，只动画 `transform` 和 `opacity`，不动画布局属性。
- 不用于普通文本链接、Modal 遮罩、拖拽手柄、长列表行或需要系统原生反馈的控件。

## 列表和筛选页

适用于活动、艺人、拍立得。

通用要求：

- 顶部使用明确页面标题，例如「艺人管理」「电子切册」。
- iOS 独立 Stack 的普通滚动页保持底部 edge-to-edge，不用外层 `SafeAreaView` 隔出固定空白；滚动容器使用 `contentInsetAdjustmentBehavior="automatic"`，内容末尾间距保留在可滚动区域内。Android 继续使用底部安全区保护。
- 搜索和筛选统一走 `SearchFilterBar` + `FilterSheet`。
- 已生效筛选默认在搜索框内以 chip 展示，可点击移除；电子切册和所有活动页例外，只通过筛选按钮激活态与数量 badge 表达，避免条件挤压搜索输入。
- 空态要说明下一步，例如新建活动、导入艺人、添加拍立得，而不是只写「暂无数据」。
- 大列表优先使用 `FlatList` 或虚拟化结构，不要用长 `ScrollView`。

艺人管理特殊要求：

- 新建艺人默认不设置类型；列表支持未设置、个人和团体筛选。
- 艺人管理页首次展示一张可关闭的说明卡，解释设置类型会启用多团体履历与日期感知活动关联；关闭后不再展示，统计页不提供入口。
- 编辑页的类型选择位于默认收起的高级内容。已有普通所属的记录需要从「设置 → 数据管理 → 艺人类型转换」整组转换，不能单独破坏关系。
- 个人可同时拥有多个当前团体；基础摘要只显示当前所属，完整时间履历放在高级内容或详情信息中。
- 团体编辑页可选择当前个人成员；入团和最后在团日期仅在高级内容展开后显示。移除当前关系默认把最后在团日期设为今天并保留历史，再次加入生成新的一段。
- 类型未设置的记录继续使用无日期普通所属；它与个人或团体不能建立所属关系，也不触发活动、单推、收藏和统计的间接命中。
- 批量类型转换只处理未设置记录。页面顶部可依据普通所属生成转换预览：成员推测为个人、上级推测为团体；预览结果集中进入「已选择」区域，方便在提交前完整确认。普通所属以关系卡片为选择单位：团体主行直接承载整组勾选，成员在同一卡片内缩进展示，不额外增加位于艺人上方的选择标题行。页面提供「全选 / 取消全选」并覆盖关系组与孤立艺人；全选时关系组使用推测类型，孤立艺人默认设为个人，仍可在右侧改为团体。下方未选择区域支持按团体或成员搜索。关系组及组内艺人都按直接关联活动数量优先展示，并显示活动场数。多层结构因中间节点角色冲突而整组禁用并提示先整理所属。用户检查后再统一确认转换。

电子切册页特殊要求：

- 作为底部 tab 主页时，底部入口名使用「切册」，页面标题使用「电子切册」。
- 搜索框保持固定高度，不显示筛选 chip，placeholder 使用「搜索艺人、活动或备注等关键词」。搜索覆盖艺人名称/简称/所属团体、活动标题、Record 备注、Item 备注和明确日期格式；多关键词使用 AND 语义，不搜索价格、数量、收藏、背签、图片状态或规格等结构化属性。
- 相册与记录共用会话级关键词，但分别保留各自筛选。搜索或筛选生效且存在结果时，相册显示「N 张拍立得」，记录显示「N 条记录」；空结果不回显关键词。有关键词时空态只清除搜索，只有筛选时才清除当前模式筛选。
- iOS 使用原生大标题和 NativeTabs；普通 `ScrollView` 向下滚动时由系统最小化 tab bar，`FlatList` 页面受 Expo 当前集成限制，不强制模拟同一行为。Android 使用 `AndroidCompactTabHeader` / `AndroidLargeTabTitle`，滚动时标题收起并驱动底部 tab bar 收起。
- iOS 与 Android 的右上角「显示选项」统一打开 Bottom Sheet，选项立即生效并持久化；浏览模式使用「相册 / 记录」，不显示 Record / Item 等数据模型术语。新增拍立得仍使用独立的最右侧 `plus` 按钮。
- 有图拍立得和记录要一起呈现和统计。
- 图片缩略图比例由 Item 规格派生，完整显示且不裁切。Record 详情保持固定三列列宽并允许缩略图高度随规格变化；按艺人和相册视图保持稳定网格，不使用瀑布流。
- “记录”用于浏览每次拍摄或购买，“相册”用于浏览全部已添加图片的拍立得；无图记录不进入相册。
- “记录”按业务日期分月显示，每条记录是一个独立条目并跳转到对应记录详情。月份间和月份内都遵循记录排序；未填写日期的记录进入末尾的“日期未填写”，不能使用创建时间冒充业务日期。
- “记录”模式使用紧凑的横向卡片：默认在左侧以固定的小尺寸显示单张代表图或最多三层的轻叠图片，无图记录在相同位置显示图片占位；右侧集中展示艺人、日期、活动和总数量，保持有图与无图记录的结构稳定。记录卡不展示价格或图片状态摘要。记录模式不显示图片大小设置，提供「显示 / 隐藏」缩略图选项。
- 选择「隐藏」缩略图后，记录卡左侧改用 `OshiAvatar`，隐藏次级艺人名称并适度降低内容高度；纵向留白应保证标题、活动和日期信息易于扫读，不能因追求紧凑而拥挤。该偏好持久化，默认显示，不能影响相册模式的图片大小设置。
- 记录卡正文固定为三行：艺人名称、日期、活动名称。日期使用主文字色和较高字重，格式包含完整年月日与星期；未填写时明确显示「日期未填写」，不能用创建时间冒充。活动名称使用小型 `music` icon，单行截断；未关联活动时显示「未关联活动」。不显示「全部有图」等图片状态摘要，总张数固定在卡片右侧。
- 记录卡只显示总张数，不显示「有图 / 无图」等图片状态摘要，也不使用「还可添加」等容易产生待办含义的表述；更多图片通过代表图上的 `+N` 提示，完整图片浏览留给 Record 详情和相册模式。
- 记录和相册分别持久化最新在前 / 最早在前排序。相册按艺人时，排序只影响组内图片；艺人组继续按单推、收藏和最近活跃顺序排列。
- 相册提供按艺人 / 按日期 / 不分组三种方式。按日期使用自然日标题；未填写日期的图片固定放在最后。
- 相册网格图片大小使用大 / 中 / 小三档，默认大图；同一可用宽度下每行数量必须是不同整数，手机宽度对应 3 / 4 / 5 列，宽屏可按同一增量增加列数。
- 相册可选择“统一比例 / 按规格”，默认统一比例。统一比例时所有缩略图使用一致纵向区域；按规格时每张图片位于圆角的正方形背景卡片中，再按拍立得规格横竖等比例完整显示，内部图片使用轻微实体阴影表达层次。两者都不裁切内容，不添加仿拍立得白边外框。
- 显示选项把「浏览模式」设计为最重要的主选择，并将当前模式对应的设置放在明确的从属区域。相册模式被选中时默认醒目说明「仅展示已添加图片的拍立得」，并引导用户到记录模式查看无图记录；提示可通过右上角关闭按钮移除，关闭后不再显示（偏好持久化）。其他单项设置不添加重复说明文字。每组选项把默认值固定在最左侧：相册、按艺人、最新在前、大、统一比例、显示缩略图。
- 设置页「切册默认视图」通过 AsyncStorage 持久化，决定每次冷启动进入切册页时的初始浏览模式（相册 / 记录）；页面内切换浏览模式仍即时生效并持久化，不覆盖默认视图设置。
- 记录使用 `ManualChekiEntryList`，不要混成假图片格。
- 拍立得日期口径要明确，避免不同页面显示不一致。
- Record 与 Item 分别维护会话级筛选：日期、艺人等筛选先在 Sheet 草稿中修改，只有点击「应用」才刷新结果；滑动、遮罩或返回关闭时丢弃草稿。日期支持日、月、年和自定义范围。Record 额外支持图片状态及正向的活动/备注/有背签条件；Item 额外支持规格及正向的活动/备注/收藏/有背签条件。筛选面板中日期之下先为「图片状态」（仅记录模式），「无图片 / 部分有图 / 全部有图」单独成节；再下方为「其他条件」，包含正向快捷条件，规格组位于最后。各组在页面内换行、不横向滑动、不折叠，可通过“全部”或再次点击清除。Chip 触控目标不低于 44×44；「单推」「收藏艺人」快捷 chip 位于艺人分区选择器上方。搜索不属于本轮筛选状态。

Record 新增、详情和编辑：

- `/cheki/new` 创建一条 Record，图片区域位于数量之前；用户可以先选图，也可以不添加图片而只填写数量。图片与数量直接顺序排列，不使用「或」作为分隔提示。
- 相册选择器单次最多选择 20 张，可分多次选择，不用当前数量限制选图；图片数超过已填数量时自动提高数量，移除图片不自动降低数量。
- 新增时必须选择艺人，或主动点击一次「暂不关联艺人」；已有空艺人 Record 在编辑时视为已经确认。
- 每张新增图片先创建为 Item 的正面；背面、收藏和 Item 备注不放进首轮 Record 表单。Record 表单的高级信息可设置本次新建 Item 的受控规格，编辑 Record 时不覆盖已有 Item。
- 价格只填写「单价（每张）」并保存非负整数；留空按 ¥0 保存。创建时默认沿用该艺人最近一张拍立得的单价（包括 ¥0），并批量应用到本次新增 Item；不覆盖本次手动输入。
- 输入完整日期后自动展示同日活动候选，活动仍由用户点击确认，不静默关联。
- `/cheki/records/[id]` 展示 Record 摘要、有图 Item、有图数量和 Record 备注；不为尚未添加图片的 Item 生成虚假图片卡。
- `/cheki/records/[id]` 概览卡片标题为艺人头像 + 名称，日期紧随标题下方（完整年月日与星期，未填写时显示「日期未填写」）；数量、有图和总价使用同一摘要行，不使用嵌套数据卡。关联活动独立成概览卡片下方的 section，使用 `EventCard`（compact，cardAlt 底 + divider 边框），未关联活动时不显示该 section。拍立得区域显示有图状态，保持三列固定列宽，缩略图高度可由各 Item 规格派生。图片数量小于 Record 数量时，网格末尾只显示一个添加占位项，点击进入编辑页图片区域；不为每个缺图数量生成占位项，也不提供网格外的独立添加按钮。
- `/cheki/records/[id]` 展示由 Item 单价派生的 Record 总价；单张查看器和 Item 编辑页展示单张单价。
- `/cheki/records/[id]/edit` 复用新增表单，可以修改 Record 字段、继续添加图片和暂存移除已有 Item；所有修改在保存时统一提交，取消编辑不改变数据库。
- 所有数量行统一进入 `/cheki/records/[id]`，不再进入旧手动记录编辑页。历史 `/cheki/manual/[id]/edit` 地址重定向到 Record 编辑页；历史 `/cheki/[id]/edit` 地址重定向到 Item 编辑页，不能再执行旧写入逻辑。
- 不提供单独的 Item 新建页；新增图片始终从 Record 新增或编辑流程进入。
- `/cheki/items/[id]/edit` 编辑已有单张：正面支持添加和替换，但已有正面不能移除；背面支持添加、替换和移除。页面同时支持单张收藏、单张备注，以及高级信息中的五种受控规格。数据层也必须拒绝将已有正面更新为空。
- Record 查看器按正面、背面浏览实际图片；正反面共享收藏和规格，并提供收藏、编辑和删除整张拍立得的快捷入口。
- 拍立得同时保存正反面时，全屏查看器顶部显示正反面切换按钮：查看正面时使用「查看背面」，查看背面时使用「查看正面」；只有单面时不显示。背面不是相册浏览序列中的独立图片，左右滑动只遍历每张拍立得的代表正面；背面仅在用户主动点击切换按钮后临时显示，滑到下一张时恢复正常正面浏览。该操作属于 `ChekiViewerModal`，不能出现在活动资料图等普通图片查看器中。
- 所有拍立得大图查看入口使用同一套收藏按钮、激活状态和更新行为；电子切册、艺人详情、活动详情与 Record 详情之间的收藏状态必须保持同步。所有编辑入口统一进入 `/cheki/items/[id]/edit`，支持正面、背面、收藏、备注和规格，不再进入旧的单图编辑页。
- 删除图片不减少 Record 总数量；删除实体 Item 时同步减少数量。单独移除背面后保留 Item，删除整张拍立得才移除实体 Item。
- 用户可见文案使用「添加图片」「已添加」「已保存」，不使用「归档」描述图片状态或操作。

Chekiroku 导入：

- `/tools/chekiroku-import` 按「选择文件 / 确认导入 / 导入结果」组织，不在同一长页面中追加完成状态。
- 确认页首先展示将导入的拍立得总数，其次展示记录、成员和团体数量；不向用户展示数据库版本、源表行数、Item、表名或字段名。
- 艺人处理区分别说明新增与匹配已有的成员、团体数量，并允许从 Bottom Sheet 查看完整名单。匹配到 Chekiroku 收藏成员时会把已有艺人同步设为收藏，必须在「需要留意」和最终确认中说明影响。
- Chekiroku 标记为同一人的成员统一称为「重复成员」；每组都必须由用户明确选择分开保留或合并目标，不能静默使用默认值。多组待处理时允许主动选择「全部分开保留」。
- 头像、日期、活动、会场、类别、隐藏状态、排序和纪念日等兼容性差异归入「需要留意」，使用结果导向的用户文案，不展示记录 ID 或导入器诊断文本。
- 页面底部使用固定操作栏，按钮写明实际导入张数；存在未处理的重复成员或无法导入的记录时，按钮说明阻塞原因并保持不可用。
- 页面只承诺不会删除或替换现有记录，不使用「不会覆盖现有数据」等会掩盖收藏状态同步的绝对表述。
- 开始写入前使用简短确认 Bottom Sheet，复述新增/匹配艺人数量、已有艺人收藏状态同步和重复导入风险。导入事务成功后展示独立结果页，主操作进入电子切册的记录模式，次操作返回工具箱；失败时保留当前预览和用户选择，允许直接重试。

## 日历规范

文件：`app/(tabs)/calendar/index.tsx`

日历仅保留月视图；右上角菜单按键进入日历设置（`/settings/calendar`），不再提供视图切换。

月视图原则：

- 月格保持轻量，只显示日期层面的信号，不变成图片墙。
- 月份标题可点击，弹出月份选择器（视觉与交互复用统计页月份选择器：年份导航 + 12 个月网格）；选择后切换到对应月份并保留原日期，原日期超出所选月份天数时取当月最后一天。
- 月视图周起始日可在「设置 → 偏好 → 日历 → 日历周起始日」选择周日或周一，默认周日；切换只影响月视图排布，不改变日期存储、统计等其他模块。
- 月视图展示可在「设置 → 偏好 → 日历 → 月视图展示」分别开关拍立得图片、活动信息、重要日期，默认全部开启；关闭后月格不再渲染对应信号，选中日期的详情面板不受影响。同时关闭活动信息和重要日期时，拍立得照片上移、月格行高略微收窄，且该模式下各行高度保持一致。
- `markedDates` 和 multi-dot 负责密度提示。
- 月格内的活动信号卡只展示活动标题，不展示时间；卡片不加左侧圆点，文字截断使用 clip 不带省略号，以容纳尽可能多的标题文字；同日多场活动按时间排序，超出上限时折叠为「+N 项」。
- 月视图不套整块卡片容器，日历直接浮在页面背景上；月格信号卡和计数点按 `screen` 背景配色，不依赖卡片底色。
- 更详细的活动、拍立得和艺人摘要放在选中日期面板。
- 活动按“活动 + 日期”展示：同日多场只显示一次，只有场次跨日期时才在不同日期分别显示。

拍立得相关：

- 拍立得数量以 `cheki_records.quantity` 聚合；有图数量由至少拥有一张 Image 的 Item 数派生。
- 日历月格的照片堆和当天「拍立得」预览中的照片都是裸图展示：无白色相纸边、无描边；月格照片堆最多叠放 3 张真实照片（最新在前，第二、第三张依次叠后），「拍立得」预览中堆叠与单张照片统一使用一圈紧致小阴影表达层次。
- 艺人摘要与统计页排行复用 `ArtistRankingList`；选中日期的排行默认展示前十并可展开完整列表，切换日期时恢复折叠。
- 如展示拍立得日期，必须明确 date/event date/created_at 的优先级。

## 统计规范

文件：`app/(tabs)/stats/index.tsx`

统计页用于回顾和比较，不只是展示数字。

顶层 section 的显示、隐藏、排序、设置入口、未来新增项提示和按需查询规则见 `docs/product/stats-customization.md`。

- 标题下方使用一个居中的时间范围控件：Expo 原生分段控件切换 `周 / 月 / 年 / 自定义`。下方周期导航两侧使用前后箭头，中间按周显示日期范围、按月显示 `YYYY 年 M 月`、按年显示 `YYYY 年`；日期文本在左右箭头之间独立居中，不显示额外下拉图标。点击中间值后，周进入日历、月进入月份选择器、年进入年份选择器。统一的 `StatsRangePicker` 根据本次点击显式传入的模式渲染对应选择器，不依赖当前已生效范围；自定义使用约 66% 屏幕高度的底部弹出卡片，标题为「选择日期范围」，支持自由选择开始和结束日期，日期输入自动补齐中横杠，并仅额外提供「全部时间」快捷操作。日期范围弹窗不重复展示顶部日期摘要，也不显示右上角关闭图标；控件随页面内容滚动且不吸顶；切换范围保持当前滚动位置和旧内容，待新统计结果就绪后原位更新。
- App 冷启动默认本月，不持久化时间范围；同一次运行期间保留当前范围和最近一次自定义范围。已经选择过自定义日期时，从周、月或年切回「自定义」直接恢复最近范围，不再次弹出选择器；点击第二行日期仍可重新编辑。显式路由范围优先于默认值。
- 本周跟随系统地区的周起始设置；本周、本月和本年均为完整自然周期。自定义范围首尾包含、允许未来日期且不限制跨度。
- 自定义范围使用 `react-native-calendars` 的单月日历，左右翻月或滑动切换月份，并提供 `YYYY-MM-DD` 开始和结束日期手动输入；无效日期或倒序范围显示行内错误且不可应用。日历范围标记只计算当前可见月份，避免超长范围拖慢选择器。点击「应用」后更新日期范围，选择「全部时间」立即应用，关闭卡片不改变当前范围。
- 趋势图按范围跨度自适应为日、月或年分桶；密集日粒度保留每天的数据柱，缩窄柱体和间距，零值仅保留弱基线。周、月视图显示非零柱顶数值，只有当柱顶数字间距过近且数值相同时才省略重复数字；横轴标签优先显示有数据的日期，标签保持单行。年视图横轴固定展示 1–12 月，不省略月份。图表保持纯展示，不增加触摸选中交互。活动按首场日期归属，拍立得继续使用填写日期并以创建时间兜底。
- 统计卡片下钻到活动或切册列表时继承相同时间范围。
- iOS 与 Android 的统计页右上角使用设置 icon（与电子切册「显示选项」一致），进入 `/settings/stats`；全局设置的「外观」分区也进入同一页面。
- 统计文案保持短、具体且以结果为中心：所选时间使用「所选时间」表达，设置分区使用「显示 / 隐藏」，还原布局不使用 danger 语义。时间范围使用完整的「自定义」表达。
- 六个顶层 section 支持全局显隐和排序；隐藏项不执行专属统计查询，共享查询按所有可见 section 的依赖并集执行。
- SectionHeader 使用 3x16 accent 竖线、17/700 标题、`lineHeight: 35`、可选 count badge 和右侧 action。
- StatBox 数字使用 28/900，compact 可降到 24。
- 统计页顶部摘要已移除，不再按所有时间、年度或月度展示摘要卡。
- 排行、支出、月度分布应优先解释口径，避免用户误解。
- 活动 section 内包含「艺人排行」卡片；它只统计显式设为团体且直接参与的已完成活动，使用 `ArtistRankingList` 展示，默认展示前十并可展开完整排行。
- 活跃度 section 使用 `react-native-chart-kit` v2 `ContributionGraph` 展示「年」口径的已完成活动与拍立得综合记录。只有存在已完成活动的日期会点亮：1 级为仅活动，2 级为活动加 1–5 张拍立得，3 级为活动加超过 5 张拍立得；只有拍立得的日期保持空白。支持横向滚动，轻点后显示当天活动场数与拍立得张数；未选择日期时不显示操作提示。周、月和自定义口径不加载每日聚合，只显示「选择“年”查看活跃度 / 仅支持年度视图」。
- 支出 section 使用「支出最高的活动」展示花费最高的五场活动，使用 `EventRow`，副文本为日期与门票/特典花费（日期段不加 icon），右侧为总花费，不显示进度条；行高 70 并垂直居中，保持易读和易点按。每一行保持对称的上下内边距，列表卡片不再额外叠加底部内边距，使最后一行在上一条分隔线与卡片底边之间保持居中。

## Platform Tab Bars

入口：`app/(tabs)/_layout.tsx`。平台实现分别位于 `src/navigation/app-tab-navigator.ios.tsx` 和 `src/navigation/app-tab-navigator.tsx`。

两端均保持 5 个可见 tab，顺序固定为首页、日历、切册、统计、我的。

iOS：

- 使用 Expo Router `NativeTabs`，不自行模拟系统 Liquid Glass 材质。
- 图标通过 `AppIcon` 的业务名映射生成 Lucide glyph，再交给 `NativeTabs.Trigger.VectorIcon`；导航配置不直接写具体 glyph 名。
- 未选中态使用 `textSecondary`，选中态使用 `accent`。
- 使用 `minimizeBehavior="onScrollDown"`；系统负责紧凑形态、恢复动画和安全区。
- iOS 不复用 Android 悬浮 Tab 的显隐状态机；页面滚动只保留自身需要的标题动画，Tab 收起完全交给 NativeTabs。
- NativeTabs 负责底部安全区；页面 `paddingBottom` 只保留内容末尾的视觉间距，不手工补偿原生 Tab 高度或滚动指示器 inset。

Android：

- 使用 `src/navigation/CustomFloatingTabBar.tsx`。
- 结构是 5 个等宽悬浮胶囊 tab。

Shell：

- `borderRadius 32`，左右留 `FLOATING_TAB_BAR_HORIZONTAL_MARGIN`，当前为 12。
- 可见基础高度为 66，选中胶囊高度 58，保留图标和文字 label 的上下呼吸感。
- 使用主题半透明纯色、边框和阴影构成外壳。
- 选中态是跟随 `selectedIndex` 的轻量圆角胶囊，使用 reanimated `withSpring`，不做高饱和实心块。
- tab icon 19px，文字 label 使用约 10.5px / 13px，单行显示；当前五个入口均为 2 字 label。
- 聚焦态主要通过 accent 色、胶囊背景和轻微 scale 表达。不要为了恢复 filled/outline 效果强行使用不符合语义的 Lucide 变体。

底部导航不承载新建活动入口。新建活动入口使用页面右上角 header icon button，点击进入 `/events/compose`。

活动解析页统一使用「公告链接」和通用预填文案。支持的链接按格式自动进入对应解析流程；界面不展示来源品牌，也不额外宣传某个外部来源。结构化链接解析结果继续进入既有草稿、未知艺人确认和活动表单流程。

## 图片和媒体

### 艺人详情背景图模式

- 背景图使用 edge-to-edge Hero，竖屏首屏高度约为可视高度的 70%，并限制在屏幕宽度的 1.6 倍以内以兼顾宽屏。艺人名称和紧凑元信息放在图片底部左侧；背景图已经承担身份表达时，不重复展示中央头像。
- iOS 的「活动 / 拍立得」切换复用统计页同款 Expo 原生 `SegmentedControl`，并根据普通页面主题或背景图明暗设置 appearance；Android 保留有边框的主题分段控件。iOS 26+ 的顶部返回和编辑控件继续使用 Liquid Glass，旧系统或开启「降低透明度」时回退为有边框的半透明实体控件。Liquid Glass 不用于月份标题、EventCard 或其他内容卡片。
- 「活动 / 拍立得」分段控件固定在完整背景图底部，左右保留 16px、底部保留 10px；扩展出的约 96px 区域属于同一张图片，并渐变到图片派生底色，控件下方直接进入实体活动列表或拍立得网格，不额外预留一整段空白。过渡区不得重新渲染或重新裁切第二张背景图。切换时两类内容保持挂载，仅切换可见层，避免 Hero、背景图和玻璃控件重建闪烁。
- Hero 滚出后，艺人名称进入紧凑导航栏；分段控件保留在 Hero 底部并随内容一起滚出，不吸附到导航栏下方。切换内容时保留各自滚动位置，用户回到页面顶部后再切换活动和拍立得。
- 单推、收藏、所属和链接以无背景的紧凑媒体操作呈现，不堆叠多个大胶囊。
- 图片提取色只作为低饱和环境色混入页面底色。深色背景保持近黑基底，卡片使用低对比度的浅色透明层，避免形成黑色卡片墙。
- 背景图模式的活动列表继续复用 `buildEventMonthSections` 和 `EventCard`；月份标题切换为无 accent 竖线、无数字 badge 的媒体式标题，普通艺人详情和所有活动页保持现有 section 样式。

### 缩略图

- 拍立得缩略图使用 54:86 比例，圆角 10。
- iOS 拍立得小组件保留完整的 54:86 图片比例：小号展示当前 1 张；中号把当前张放在中间，两侧展示接下来两张，少于 3 张时按实际数量居中，不重复图片补位。每次同步从最近拍摄的照片开始，并按拍摄时间从新到旧轮播，每张图片依次成为当前张。
- 拍立得小组件的艺人筛选来自 `/settings/widget`。默认包含全部有图拍立得；选择一位或多位艺人后只缓存并轮播 `artist_id` 属于所选艺人的照片，保存设置后立即刷新时间线。
- iOS「下一场活动」小组件与「拍立得回忆」独立注册，仅支持小号和中号，不增加设置入口。小号显示自然日倒计时、标题、日期和活动时间；中号左侧显示活动第一张资料图（无图时回退倒计时块），右侧按标题、日期时间、地点纵向左对齐；同时有开场和开演时间时都显示，两者都为空时显示「全天」。
- 首页活动 Hero 与下一场活动小组件共同使用 `src/utils/currentEvent.ts` 的选择规则：只考虑今天及之后的 `planned` 活动；当天按代表时间边界切换，代表时间优先取开场时间、没有开场时取开演时间；未计时活动在首场计时活动开始前优先显示；相同时间或多个未计时活动按创建时间稳定排序。
- App 冷启动完成数据库初始化、回到前台及活动新增/编辑/删除时，静默把日期早于本地今天的 `planned` 活动改为 `completed`，然后刷新小组件。小组件不生成午夜或活动开始时间的未来 timeline，因此 App 未打开时允许保留最近一次同步快照。
- 有活动的小组件整块跳转到 `/events/:id`；空态显示「还没有下一场活动」和「轻点添加计划中的活动」，整块跳转到新建活动流程。需在浅色、深色和 Home Screen tinting 模式检查可读性与深链。
- 活动资料图按页面空间选择网格或横向列表，但需要稳定尺寸，避免图片加载后布局跳动。
- 艺人头像统一圆形，通过 `resolveAvatarSource()` 解析普通 URI；私有构建可额外解析构建时注入的 `preset://` 资源。

### 全屏查看

- `Modal transparent`，`presentationStyle="overFullScreen"`，`animationType="fade"`。
- 背景 `rgba(0,0,0,0.92)`。
- 顶部左侧保留圆形半透明关闭按钮；右侧按当前内容能力显示切换正反面、收藏和编辑操作。删除作为底部 destructive 操作；没有顶部操作能力时保留等宽占位，确保图片计数居中稳定。

## 图标

图标库：`@react-native-vector-icons/lucide`。

代码入口：`src/components/AppIcon.tsx`。

规则：

- 页面和组件只使用 `AppIcon` 的业务名，不直接 import `@react-native-vector-icons/lucide`、`@expo/vector-icons` 或具体 icon 字体。
- 图标命名遵循「业务名 -> 映射层 -> Lucide 实际名」。例如页面使用 `favorite`、`calendar`、`disclosure`，映射层再决定实际 glyph 是 `heart`、`calendar-days` 还是 `chevron-right`。
- iOS 原生 Toolbar 优先使用 SF Symbols，但仍通过 `AppIcon` 的业务名映射获取，页面不直接硬编码 symbol 名；其他页面图标继续使用 Lucide glyph。
- 首页、所有活动、艺人管理和重要日期的 iOS 右上角「新建」统一复用 `NativeAddToolbar`，由原生 `Stack.Toolbar` 渲染 `plus`；Android 保留现有 Lucide Header 操作。首页右上角另有设置 icon（与电子切册「显示选项」一致），点击进入 `/settings/home` 自定义设置界面。底部 Tab Bar 不随本轮 Toolbar 调整变更。
- iOS 导航栏中的「取消 / 编辑 / 保存 / 重置」等文字操作统一使用原生 `Stack.Toolbar.Button`，避免两字自定义按钮在 Liquid Glass 下收成圆形；Android 保留现有 Header 操作。
- 只有会丢失持久数据或用户配置的操作使用 danger 红色，例如删除记录、覆盖备份；取消、清除筛选、还原默认布局等非破坏性操作继续使用普通强调色。破坏性操作需要二次确认，确认按钮使用 destructive 语义。
- 新增图标先扩展 `AppIconName` 和 `ICONS`，不要在页面内写 Lucide 实际名。
- `variant` 只用于真实业务状态或方向，例如 `selected/unselected`、`up/down/forward/back`。`active/inactive` 只有在 Lucide 实际提供有意义的状态 glyph 时才配置；否则用颜色、背景、缩放或文字表达状态。
- Lucide 不提供实心 heart。单推或收藏如果需要实心心形，必须作为 `AppIcon` 映射层的明确例外实现，而不是在页面里绕过映射层。
- tab 显示文字 label；选中态用 accent 色、选中胶囊、文字字重和轻微 scale 表达。
- 菜单项图标 18px。
- SearchFilterBar 搜索 icon 16px，筛选 icon 20px。
- EventCard 时间和地点 icon 13px。
- Header 新建活动 icon 24px。
- 单推心形 11-20px，按上下文决定。

## 交互规范

- 卡片按压：优先使用 `AnimatedPressable`，按压时轻微缩放并降低透明度；旧组件可保留 `activeOpacity` 0.72。
- HomeUpcomingHero：0.88。
- 菜单行：0.6。
- 列表项和 picker：0.7。
- Filter chip 和筛选按钮：约 0.78。

## 文案规范

界面语言：简体中文，允许混入明确的专有词，例如 チェキ、Setlist、特典、LIVE、TOUR。

规则：

- 使用简短、具体、以结果为中心的表达；面向用户描述任务，不暴露内部模型或实现细节。
- 同一概念始终使用同一术语，优先使用用户熟悉的领域词；不要为了变化而替换同义词。
- 页面与分区标题使用名词短语，操作使用能说明结果的动词；「完成」表示结束子步骤，「应用」表示让设置或筛选生效。
- 标题说明当前状态，正文只补充原因、后果或下一步，避免重复和无实际信息的语气词。
- 空态区分首次使用、无匹配结果和加载失败，并给出当前最有用的下一步。
- 错误提示使用 `title + reason + nextStep`；删除等不可恢复操作应明确对象和后果。
- 可见文案与无障碍名称保持一致；数量使用自然中文语序，数字与单位之间留空格。
- 表单必填字段在字段名后加 `*`，可选字段不额外标注「可选」。

## 可访问性和质量门槛

每个新 UI 改动至少检查：

- 普通文字对比度至少接近 WCAG AA 4.5:1，大标题和粗体大字至少 3:1。
- 触控目标不低于 44x44。
- 可点击图片、排行行、菜单行设置 `accessibilityRole` 和必要的 `accessibilityLabel`。
- 颜色不是唯一信息来源。状态需要文字、图标或位置辅助。
- 动态内容不会撑破按钮、chip、卡片或 tab。
- 深色模式下不使用过暗结构色作为文字色。
- Android 返回键能关闭 Modal。
- 长列表使用虚拟化。
