# 活动搜索与筛选

> 状态：已实现。本文冻结活动 v2 数据结构下“所有活动”页面的搜索、筛选和深链语义。

## 1. 搜索

- 搜索范围包括活动标题、备注、详情、链接、Setlist，场次标题、日期、结束日期、开场/开演/结束时间、城市、场地，时间表标题、时间与备注，以及活动归因艺人。
- 城市和场地只作为关键词搜索字段，不进入筛选面板。
- 文本先做 NFKC、大小写与空白归一；日期支持 `YYYY-MM-DD`、斜杠、点号和中文年月日等既有格式。
- 搜索词按空白分成多个 token；所有 token 使用 AND，但可分别命中聚合中的不同字段。
- 艺人搜索采用 `event_artist_attributions`：直接出演始终命中，团体出演按正式在团履历归因给个人；普通所属不参与。
- 时间表单独关联的本地艺人及其活动日期有效的正式团体也参与搜索，但不扩大艺人筛选口径。
- 存在日期筛选时，场次和时间表搜索只读取与日期范围相交的场次；活动根字段与活动级归因艺人不受此限制。

## 2. 筛选条件

- 日期：日、月、年、自定义范围，互斥；任一场次的 `[session_date, end_date ?? session_date]` 与范围相交即命中。
- 状态：多选，覆盖心愿单、计划中、已完成、已取消。
- 艺人：多选，候选只包含有活动归因结果的艺人；提供单推和收藏艺人批量快捷选择。
- 最低评分：5 星、4 星以上、3 星以上、2 星以上、1 星以上。
- 内容正向条件：有备注、有 Setlist、有时间表、有资料图、有拍立得。

同一类别的多个值使用 OR，不同类别以及搜索词之间使用 AND。筛选角标按启用类别计数；状态和艺人无论选择多少值都各算一类，内容条件各自计数。

## 3. 交互状态

- 打开筛选面板时，把已应用筛选复制为草稿。
- 面板内修改不刷新列表；点击“应用”后才提交。
- 滑动关闭、遮罩关闭和系统返回丢弃草稿。
- “重置”只清空草稿，仍需点击“应用”。
- 搜索与已应用筛选在当前 App 会话内保留，不写入 AsyncStorage。
- 搜索栏不展开筛选 chip，只显示筛选类别角标；有结果时显示活动总数。
- 搜索和筛选共同导致空结果时，“清除全部”一次清空两者。
- 筛选只决定活动是否出现；卡片代表场次、月份分组和排序继续使用活动原有规则。

## 4. 深链兼容

- 深链条件建立一套新的已应用筛选，并清空页面之前的搜索和筛选。
- 继续兼容日期、状态、艺人、最低评分和 `scope` 参数。
- 深链指定的艺人当前没有归因活动，或 `scope` 当前没有可命中艺人时，条件仍然生效并返回空结果，不得退化为未筛选的全部活动。
- 旧 `city`、`venue` 参数转为独立搜索 token；新的入口不再生成城市或场地筛选。
- 深链初始化完成后消费入口参数，避免页面重新聚焦时覆盖用户后续修改。

## 5. 内容条件口径

- 有备注：`events.notes` 去除空白后非空；`details` 不算备注。
- 有 Setlist：`events.setlist_text` 去除空白后非空。
- 有时间表：活动任一场次存在时间表条目。
- 有资料图：存在 `photos.event_id` 关联。
- 有拍立得：存在 `cheki_records.event_id` 关联。
