# ADR 0001: 可选艺人类型与时间化团体履历

- 状态：已接受
- 日期：2026-08-13
- 相关文件：
  - `docs/data/artist-data-model-design.md`
  - `src/db/artistRelationshipSchema.ts`
  - `src/db/migrations.ts`

## 背景

旧模型用 `artists.parent_id` 同时表达成员、团体和层级，并把当前树结构递归用于历史活动与拍立得统计。艺人退团后修改当前所属会改写历史统计，多团兼任和再次入团也无法表达。与此同时，旧数据无法可靠判断一条记录是个人还是团体。

## 决策

采用可为空的显式艺人类型，并把关系拆成两类：未设置记录使用无日期普通所属，已设置个人与团体使用可重复、可并行且带闭区间日期的正式履历。只有正式履历参与团体活动到个人的日期归因；拍立得始终只按直接关联统计。

旧数据和旧备份不自动推断类型。用户需要高级关联能力时，通过批量转换或编辑页高级内容明确设置。

## 理由

这避免用名称、UUID 或旧层级猜测类型，同时保留旧数据的通用能力。正式履历成为历史活动归因的唯一事实源，消除了 `parent_id` 既代表当前状态又代表历史状态的双重语义。

## 后果

- 统计团体排行只包含显式 `group` 且直接出演的记录。
- 未设置记录不会通过所属命中活动筛选、单推、收藏或统计。
- 多层旧所属无法自动变成正式履历，必须由用户整理为个人到团体或继续保持未设置。
- 若未来需要团体层级，应建立独立组织/文件夹模型，不能复用正式成员关系。
