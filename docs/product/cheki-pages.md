# 电子切册页面与记录表单

页面细节由 UI/UX 总文档迁入；跨页面规则见 [UI/UX](ui-ux.md)，产品定位见 [PRODUCT.md](../../PRODUCT.md)，术语见 [CONTEXT.md](../../CONTEXT.md)。仅在相关任务改变这些行为时更新。

筛选条件与草稿状态机见 [筛选规范](cheki-filter-refactor.md)，数据不变量见 [拍立得数据模型](../data/cheki-data-model-design.md)。

## 电子切册


- 作为底部 tab 主页时，底部入口名使用「切册」，页面标题使用「电子切册」。
- 搜索框保持固定高度，不显示筛选 chip，placeholder 使用「搜索艺人、活动或备注等关键词」。搜索覆盖艺人名称/简称/所属团体、活动标题、Record 备注、Item 备注和明确日期格式；多关键词使用 AND 语义，不搜索价格、数量、收藏、背签、图片状态或规格等结构化属性。
- 相册与记录共用会话级关键词，但分别保留各自筛选。搜索或筛选生效且存在结果时，相册显示「N 张拍立得」，记录显示「N 条记录」；空结果不回显关键词。有关键词时空态只清除搜索，只有筛选时才清除当前模式筛选。
- iOS 使用原生大标题和 NativeTabs；普通 `ScrollView` 向下滚动时由系统最小化 tab bar，`FlatList` 页面受 Expo 当前集成限制，不强制模拟同一行为。Android 使用 `AndroidCompactTabHeader` / `AndroidLargeTabTitle`，滚动时标题收起并驱动底部 tab bar 收起。
- iOS 与 Android 的右上角「显示选项」统一打开 Bottom Sheet，选项立即生效并持久化；浏览模式使用「相册 / 记录」，不显示 Record / Item 等数据模型术语。新增拍立得仍使用独立的最右侧 `plus` 按钮。
- 有图拍立得和记录要一起呈现和统计。
- 图片缩略图按图片自身比例完整显示且不裁切；图片自身比例保持不变，展示外框由规格决定。展示方式（拍立得 / 正方形网格）由设置页「外观与显示 → 拍立得展示方式」控制，影响艺人详情、活动详情、拍立得记录详情与电子切册，全屏拍立得查看器不受影响。各页面的「拍立得」模式按下述实物比例外框展示。Record 详情保持固定三列列宽，网格形态随偏好切换；按艺人和相册视图保持稳定网格，不使用瀑布流。
- “记录”用于浏览每次拍摄或购买，“相册”用于浏览全部已添加图片的拍立得；无图记录不进入相册。
- “记录”按业务日期分月显示，每条记录是一个独立条目并跳转到对应记录详情。月份间和月份内都遵循记录排序；未填写日期的记录进入末尾的“日期未填写”，不能使用创建时间冒充业务日期。
- “记录”模式使用紧凑的横向卡片：默认在左侧以固定的小尺寸显示单张代表图或最多三层的轻叠图片，无图记录在相同位置显示图片占位；右侧集中展示艺人、日期、活动和总数量，保持有图与无图记录的结构稳定。记录卡不展示价格或图片状态摘要。记录模式不显示图片大小设置，提供「显示 / 隐藏」缩略图选项。
- 选择「隐藏」缩略图后，记录卡左侧改用 `OshiAvatar`，隐藏次级艺人名称并适度降低内容高度；纵向留白应保证标题、活动和日期信息易于扫读，不能因追求紧凑而拥挤。该偏好持久化，默认显示，不能影响相册模式的图片大小设置。
- 记录卡正文固定为三行：艺人名称、日期、活动名称。日期使用主文字色和较高字重，格式包含完整年月日与星期；未填写时明确显示「日期未填写」，不能用创建时间冒充。活动名称使用小型 `music` icon，单行截断；未关联活动时显示「未关联活动」。不显示「全部有图」等图片状态摘要，总张数固定在卡片右侧。
- 记录卡只显示总张数，不显示「有图 / 无图」等图片状态摘要，也不使用「还可添加」等容易产生待办含义的表述；更多图片通过代表图上的 `+N` 提示，完整图片浏览留给 Record 详情和相册模式。
- 记录和相册分别持久化最新在前 / 最早在前排序。相册按艺人时，排序只影响组内图片；艺人组继续按单推、收藏和最近活跃顺序排列。
- 相册提供按艺人 / 按日期 / 不分组三种方式。按日期使用自然日标题；未填写日期的图片固定放在最后。
- 相册网格图片大小使用大 / 中 / 小三档，默认大图；同一可用宽度下每行数量必须是不同整数，手机宽度对应 3 / 4 / 5 列，宽屏可按同一增量增加列数。
- 电子切册、艺人详情、活动详情、拍立得记录详情及小组件筛选预览统一采用下述实物比例外框、按序补位和垂直居中规则；带图片查看器的页面同步使用补位后的展示顺序。活动详情只在当前预览范围内补位，查看器先展示预览顺序，再接续未预览图片。正方形网格保持原有等宽卡片与原图完整居中展示。
- 拍立得贴纸相机选择页、小组件选择页和手动排序页固定使用正方形网格与电子切册「中」档尺寸（手机 4 列，宽屏按相同规则增加列数），间距 4px；所有规格每张占一格，图片完整居中显示，不受切册展示偏好影响。
- 小组件设置的手动排序按正方形格子计算落点：长按拖动经过其他格子时实时预览插入顺序，周围照片立即动画让位；正在拖动的照片显示主题色圆角边框，松手确认当前顺序并清除边框；支持边缘自动滚动、取消后保留原顺序、无障碍前移 / 后移和移除。五寸仍按一张保存与计数；设置页旋转不改变桌面小组件的图片方向。
- 设置页「拍立得展示方式」页面顶部只显示当前选中样式的编号图例，复用实际排版算法；下方使用原有 SettingsChoiceCard 提供“实物比例 / 等高排列 / 方形网格”选项。实物比例下提供“允许提前补位 / 严格排序”，默认允许，图例随选项更新；偏好保存到本机并全局生效。电子切册显示选项提供同样三种样式及实物比例补位选择，仅覆盖当前会话。等高排列使用规格外框宽高比反算行高，完整行两端对齐，末行不放大；方形网格使用等宽卡片。所有图片完整显示，不旋转、不裁切。
- 各页面的“拍立得”模式采用实物比例外框：三寸竖版 54 × 86、三寸横版 86 × 54、五寸竖版 86 × 108、五寸横版 108 × 86，使用统一缩放系数；方形使用 54 × 54。按外框实际宽度和固定间距排版，全页保持统一比例尺，不做整行缩放。每行从最早尚未展示的图片开始，后续图片放不下时继续向后查找能放入的图片，按原排序优先补空；被跳过的图片保持相对顺序，优先进入下一行，补位不跨分组。图片查看器使用补位后的逐行展示顺序，左右切换与页面顺序一致。每行按最高外框确定高度，其他外框垂直居中；没有合适图片时保留余白。图片在外框内 contain 完整居中，不自动旋转或修改原图，取消此页面的横版方向控制。正方形网格保持原有展示规则。
- 显示选项把「浏览模式」设计为最重要的主选择，并将当前模式对应的设置放在明确的从属区域。相册模式被选中时默认醒目说明「仅展示已添加图片的拍立得」，并引导用户到记录模式查看无图记录；提示可通过右上角关闭按钮移除，关闭后不再显示（偏好持久化）。其他单项设置不添加重复说明文字。每组选项把默认值固定在最左侧：相册、按艺人、最新在前、大、拍立得、显示缩略图。
- 设置页「切册默认视图」通过 AsyncStorage 持久化，决定每次冷启动进入切册页时的初始浏览模式（相册 / 记录）；页面内切换浏览模式仍即时生效并持久化，不覆盖默认视图设置。
- 记录使用 `ManualChekiEntryList`，不要混成假图片格。
- 拍立得日期口径要明确，避免不同页面显示不一致。
- Record 与 Item 分别维护会话级筛选：日期、艺人等筛选先在 Sheet 草稿中修改，只有点击「应用」才刷新结果；滑动、遮罩或返回关闭时丢弃草稿。日期支持日、月、年和自定义范围。Record 额外支持图片状态及正向的活动/备注/有背签条件；Item 额外支持规格及正向的活动/备注/收藏/有背签条件。筛选面板中日期之下先为「图片状态」（仅记录模式），「无图片 / 部分有图 / 全部有图」单独成节；再下方为「其他条件」，包含正向快捷条件，规格组位于最后。各组在页面内换行、不横向滑动、不折叠，可通过“全部”或再次点击清除。Chip 触控目标不低于 44×44；「单推」「收藏艺人」快捷 chip 位于艺人分区选择器上方。搜索不属于本轮筛选状态。

按活动快速添加：

- 活动详情的拍立得区域保留「添加」完整表单入口，并提供「按活动快速添加」入口（`/cheki/event-quick-add`）。
- 默认将参演团体展开为活动日期有效的所属成员，直接参演的个人或未设置类型艺人继续展示；按艺人 ID 去重，使用共享个人优先排序（单推、收藏个人、其他个人、团体、未设置类型），同档保持原顺序，搜索补入后也遵守同一排序，团体本身通过搜索添加。数量为 0，支持加减按钮和直接输入数量。其他艺人通过共享艺人选择器搜索补入；团体未设置成员时显示搜索添加引导，不改变活动的出演者列表。
- 艺人录入使用同一卡片内的紧凑列表，表头统一标明数量与单价；每行集中展示头像、姓名、数量加减及单价，行间用分隔线区分。输入和加减按钮至少 44px 高；空间不足时允许换行，姓名最多两行。
- 活动固定为来源活动；记录日期默认活动日期，可修改为有效日期。单价沿用各艺人最近一张拍立得的单价（包括 ¥0），无历史时为 ¥0；手动输入后不被异步价格读取覆盖。
- 汇总本次张数与总价，只为数量大于 0 的艺人分别新建记录，不合并或覆盖已有记录。数量与单价为非负整数，留空按 0；不在此流程上传图片，可保存后从记录编辑补充。
- 整批保存使用一个事务，失败全部回滚、保留草稿供重试；成功返回活动详情。未保存的修改离开时需要确认。

Record 新增、详情和编辑：

- `/cheki/new` 创建一条 Record，拍立得数量位于图片区域之前；用户可以先填写数量，也可以不添加图片而只保存数量。数量与图片直接顺序排列，不使用「或」作为分隔提示。
- 相册选择器单次最多选择 20 张，可分多次选择，不用当前数量限制选图；图片数超过已填数量时自动提高数量，移除图片不自动降低数量。相册单次选择上限与默认规格说明合并为一张信息提示卡，以「图片与规格」为标题，两项说明在正文中分点呈现；右上角可关闭，关闭状态持久化。
- Record 表单的图片状态简短显示「已添加：N 张拍立得」或「暂无图片」，不使用 `N / quantity` 表达，避免把 Record 数量误解为图片上限。底部只汇总拍立得总数，不重复图片数量；表单不额外显示自动增加数量的提示。
- 新增时必须选择艺人，或主动点击一次「暂不关联艺人」；该操作使用完整宽度的中性次级按钮，不表现为普通文字链接。艺人搜索有关键词且无匹配结果时，在候选列表上方显示带搜索名称的「新建艺人」快捷按钮；点击后按该名称创建未设置类型的艺人并自动选中，创建失败时保留搜索词并提示。已有空艺人 Record 在编辑时视为已经确认。
- 每张新增图片先创建为 Item 的正面；背面、收藏和 Item 备注不放进首轮 Record 表单。新增 Item 的规格按图片比例自动推断方向（宽 > 高为横版，否则为竖版，尺寸族默认三寸，不推断方形），不提供批量规格选择；编辑 Record 时不因新增图片的默认值覆盖已有 Item，用户主动修改「单价（每张）」时批量更新保留 Item 的单价，规格等单张属性仍在单张编辑中手动修改。
- 价格只填写「单价（每张）」并保存非负整数；留空按 ¥0 保存。创建时默认沿用该艺人最近一张拍立得的单价（包括 ¥0），并批量应用到本次新增 Item；不覆盖本次手动输入。
- 输入完整日期后自动展示同日活动候选，活动仍由用户点击确认，不静默关联。
- `/cheki/records/[id]` 展示 Record 摘要、有图 Item、有图数量和 Record 备注；不为尚未添加图片的 Item 生成虚假图片卡。
- `/cheki/records/[id]` 概览卡片标题为艺人头像 + 名称，单推艺人沿用单推头像样式并在名称旁显示单推标签；日期紧随标题下方靠左（完整年月日与星期，未填写时显示「日期未填写」）；数量、有图和总价使用同一摘要行，不使用嵌套数据卡。关联活动独立成概览卡片下方的 section，使用 `EventCard`（compact，cardAlt 底 + divider 边框），未关联活动时不显示该 section。拍立得区域显示有图状态，保持三列固定列宽；「拍立得」时使用竖版外框，正方形网格时使用圆角背景卡片，图片均按自身比例居中完整显示、不撑满整格。图片数量小于 Record 数量时，网格末尾只显示一个添加占位项，点击进入编辑页图片区域；不为每个缺图数量生成占位项，也不提供网格外的独立添加按钮。
- `/cheki/records/[id]` 展示由 Item 单价派生的 Record 总价；单张查看器和 Item 编辑页展示单张单价。
- `/cheki/records/[id]/edit` 复用新增表单，可以修改 Record 字段、继续添加图片和暂存移除已有 Item；所有修改在保存时统一提交，取消编辑不改变数据库。
- 所有数量行统一进入 `/cheki/records/[id]`，不再进入旧手动记录编辑页。历史 `/cheki/manual/[id]/edit` 地址重定向到 Record 编辑页；历史 `/cheki/[id]/edit` 地址重定向到 Item 编辑页，不能再执行旧写入逻辑。
- 不提供单独的 Item 新建页；新增图片始终从 Record 新增或编辑流程进入。
- `/cheki/items/[id]/edit` 编辑已有单张：正面支持添加和替换，但已有正面不能移除；背面支持添加、替换和移除。页面同时支持单张收藏、单张备注，以及「更多」分组中的五种受控规格。数据层也必须拒绝将已有正面更新为空。
- Record 查看器按正面、背面浏览实际图片；正反面共享收藏和规格，并提供收藏、编辑和删除整张拍立得的快捷入口。
- 拍立得同时保存正反面时，全屏查看器顶部显示正反面切换按钮：查看正面时使用「查看背面」，查看背面时使用「查看正面」；只有单面时不显示。背面不是相册浏览序列中的独立图片，左右滑动只遍历每张拍立得的代表正面；背面仅在用户主动点击切换按钮后临时显示，滑到下一张时恢复正常正面浏览。该操作属于 `ChekiViewerModal`，不能出现在活动资料图等普通图片查看器中。
- 所有拍立得大图查看入口使用同一套收藏按钮、激活状态和更新行为；电子切册、艺人详情、活动详情与 Record 详情之间的收藏状态必须保持同步。所有编辑入口统一进入 `/cheki/items/[id]/edit`，支持正面、背面、收藏、备注和规格，不再进入旧的单图编辑页。
- 删除图片不减少 Record 总数量；删除实体 Item 时同步减少数量。单独移除背面后保留 Item，删除整张拍立得才移除实体 Item。
- 用户可见文案使用「添加图片」「已添加」「已保存」，不使用「归档」描述图片状态或操作。
