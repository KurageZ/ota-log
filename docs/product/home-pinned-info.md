# 首页置顶信息功能设计

> 状态：已实现。
>
> 本文定义首页顶部固定英雄卡的产品边界、设置入口、展示规则和验收标准。后续如有新取舍，应先更新本文档。

## 背景

当前首页已经支持功能卡片的显示、隐藏和排序，但顶部的最近活动 hero 与普通功能卡片混在同一套首页自定义模型里。新的方向是把首页拆成两个层级：

1. 顶部固定显示一张「置顶信息」英雄卡。
2. 英雄卡下方继续显示用户自定义的功能卡片。

置顶信息承担首页第一眼的重点信息，不参与功能卡片排序，也不允许隐藏。

## 目标

- 首页顶部永远有一张英雄卡，形成稳定的首屏锚点。
- 用户可以选择英雄卡展示的内容类型。
- 原有功能卡片继续在英雄卡下方展示，并保持可排序、可隐藏。
- 设置页使用用户能理解的命名，避免暴露「英雄卡」这类实现或设计术语。

## 非目标

- 不做自由布局编辑器。
- 不支持自定义英雄卡颜色、背景图、字号或视觉模板。
- 不在第一版支持多个置顶信息轮播。
- 不因为置顶信息选择了某个类型，就自动隐藏下方同类功能卡片。
- 不把置顶信息纳入「已启用 / 未启用」拖拽列表。

## 信息架构

入口沿用现有「首页自定义」设置页，在原页面新增一个位于功能卡片列表上方的配置分区。该分区属于正常可滚动内容，不固定停留在屏幕顶部。

页面结构：

1. 置顶信息
2. 功能卡片

「置顶信息」分区只配置首页顶部固定英雄卡。「功能卡片」分区继续承载原有卡片排序、显示和隐藏。

## 置顶信息配置

分区标题：`置顶信息`

说明文案：`选择首页顶部优先展示的内容。`

配置方式：单选。

可选项：

| 选项 | 副文案 | 需要额外配置 |
|------|--------|--------------|
| 下一场活动 | 下一场计划和倒计时 | 无 |
| 关注艺人 | 一位艺人的活动摘要 | 选择 1 位艺人 |
| 本月概览 | 本月完成、计划和拍立得 | 无 |

默认值：`下一场活动`。

## 首页展示规则

### 通用规则

- 首页顶部直接展示置顶信息英雄卡，不显示 section 标题。
- 英雄卡下方才进入功能卡片区。
- 英雄卡不可隐藏。
- 英雄卡点击行为必须进入对应的详情或功能页。
- 英雄卡不应重复渲染普通模块标题，例如「未来活动」「关注艺人」「本月概览」。
- 下方「未来活动」功能卡片只在置顶信息为 `下一场活动` 时排除最近一场 planned 活动；其他置顶类型下继续展示完整未来活动列表。
- 深色和浅色模式都必须检查文字对比度、卡片边界和信息可读性。

### 下一场活动

展示最近一场 `planned` 活动。

展示内容：

- 倒计时主信息。
- 活动标题。
- 日期、时间、地点。
- 单推命中提示，如果该活动包含当前单推。

点击行为：进入活动详情页。

空态：

- 没有未来计划活动时，英雄卡仍然保留。
- 显示添加活动入口。
- 点击进入新建活动页。

建议文案：

- 标题：`还没有下一场活动`
- 描述：`添加计划中的活动后，这里会显示倒计时和活动安排。`
- 操作：`添加活动`

### 关注艺人

展示用户在「置顶信息」中选择的一位艺人。第一版只支持 1 位，避免顶部英雄卡变成列表。

展示内容：

- 艺人头像。
- 艺人主名。
- 单推标识，如果该艺人是当前单推。
- 今年已完成活动数量。
- 拍立得数量。
- 下一场相关活动，如果存在。

点击行为：进入艺人详情页。

空态：

- 如果尚未选择艺人，英雄卡显示选择入口。
- 如果已选艺人被删除或无效，回退到未选择状态。

建议文案：

- 标题：`选择置顶艺人`
- 描述：`选择一位艺人后，首页顶部会显示下一场活动和记录摘要。`
- 操作：`选择艺人`

### 本月概览

展示当前自然月摘要。

展示内容：

- 标题使用当前月份记录，例如「7 月记录」。
- 本月已完成活动数。
- 本月计划中活动数。
- 本月拍立得人数。
- 本月拍立得张数。

点击行为：进入统计页，并带上当前年月参数。

空态：

- 即使本月无数据，英雄卡也正常展示。
- 数字显示为 0，不切换为普通空态卡。
- 可用弱文案提示本月还没有记录。

建议文案：

- 标题：当前月份记录，例如 `7 月记录`

## 功能卡片关系

功能卡片区保持现有模型：

- 支持显示和隐藏。
- 支持拖拽排序。
- 支持关注艺人、本月概览、电子切册速览、最近完成等模块。
- 隐藏所有功能卡片时，英雄卡仍然显示，功能区可展示原有空态。

默认仅开启未来活动、最近完成和电子切册速览；关注艺人和本月概览保留在未启用区。

如果置顶信息选择了「关注艺人」，下方仍允许显示「关注艺人」功能卡片。

如果置顶信息选择了「本月概览」，下方仍允许显示「本月概览」功能卡片。

理由：置顶信息是首页封面，功能卡片是可展开的行动入口。两者信息密度和入口职责不同，不应由系统自动隐藏用户已经启用的卡片。

## 数据与持久化

置顶信息属于本机 UI 偏好，和现有首页自定义偏好一致，不作为核心用户内容处理。

建议新增偏好结构：

```ts
type HomePinnedInfoType = 'nextEvent' | 'featuredArtist' | 'monthSummary';

type HomePinnedInfoConfig =
  | { type: 'nextEvent' }
  | { type: 'featuredArtist'; artistId: string | null }
  | { type: 'monthSummary' };
```

默认值：

```ts
{ type: 'nextEvent' }
```

兼容策略：

- 旧版本没有置顶信息配置时，使用默认值。
- `featuredArtist.artistId` 为空或无效时，保留 `featuredArtist` 类型，但展示选择艺人的空态。
- 不从功能卡片排序中推断置顶信息配置。

## 设置页交互

「置顶信息」分区建议使用设置页现有行样式。

交互规则：

- 点击选项即切换单选状态。
- 选择「关注艺人」后，在该选项下方展示当前艺人和「更换」入口。
- 艺人选择复用现有 `ArtistSearchPicker` 或同等共享选择器。
- 重置首页设置时，置顶信息恢复为 `下一场活动`。
- 保存失败时使用项目统一失败提示模式。

## 命名

用户可见命名：

- 设置分区：`置顶信息`
- 默认类型：`下一场活动`
- 艺人类型：`关注艺人`
- 月度类型：`本月概览`

避免使用：

- `英雄卡`
- `Hero`
- `活动倒数`

说明：

- `下一场活动` 比 `活动倒数` 更准确，因为该卡片不仅展示倒计时，也展示活动标题、时间地点和单推命中提示。
- `置顶信息` 比 `英雄卡` 更贴近设置语境，用户能直接理解这是首页顶部固定内容。

## 验收标准

- 首页顶部始终渲染一张置顶信息英雄卡。
- 置顶信息不显示 section 标题。
- 功能卡片只出现在置顶信息下方。
- 首页自定义设置页包含「置顶信息」和「功能卡片」两个清晰分区。
- 置顶信息支持 `下一场活动`、`关注艺人`、`本月概览` 三种单选。
- `关注艺人` 类型支持选择 1 位艺人，并能处理未选择、已删除艺人的情况。
- `下一场活动` 在没有未来计划活动时显示添加活动入口。
- `本月概览` 在本月无数据时仍显示 0 值摘要。
- 原有功能卡片的排序、显示、隐藏能力不被破坏。
- 选择置顶信息不会自动隐藏下方同类型功能卡片。
- 重置首页设置会把置顶信息恢复为 `下一场活动`。
- 浅色和深色模式下，标题、数字、说明文字和操作入口都可读。

## 实现提示

建议把置顶信息偏好和现有首页卡片偏好放在同一个首页偏好模块中维护，但不要把置顶信息建模为普通 `HomeCardConfig`。

推荐分层：

- `homePreferences`：负责读取、保存、清洗置顶信息和功能卡片配置。
- 首页页面：负责根据置顶信息类型加载对应数据并渲染顶部英雄卡。
- 首页设置页：负责分区展示置顶信息配置和功能卡片排序。
- 现有功能卡片组件：继续保持普通 dashboard 卡片职责，不承担顶部英雄卡布局。

## 已定口径

- `关注艺人` 英雄卡同时展示下一场相关活动、今年活动数和拍立得数量。
- `本月概览` 置顶信息与本月概览功能卡片都展示已完成、计划中、拍立得人数和拍立得张数。

## 后续可能

- 置顶信息是否需要在未来支持「指定活动」，第一版暂不纳入。

## 首页页面呈现

文件：`app/(tabs)/(home)/index.tsx`

首页负责当天和近期行动。iOS 使用原生 Stack large title 和 `headerRight` 新建活动入口；Android 保留自绘折叠标题。

结构：

1. 置顶信息英雄卡，固定显示，不显示 section 标题，不参与功能卡片排序。
2. 首页自定义功能卡片区，包含未来活动时间线、关注艺人、本月概览、电子切册速览、最近完成等模块。

首页模块标题统一放在卡片外，使用 3x16 accent 竖线、17/700 标题、`lineHeight: 35`、可选 count badge 和右侧 action。卡片内部只放内容，不重复模块标题。

### 首页置顶信息

设置入口：`app/settings/home.tsx`

- 设置页「置顶信息」分区放在功能卡片排序列表上方，但属于正常可滚动内容，不固定停留在屏幕顶部。
- 置顶信息不可隐藏，只能在 `下一场活动`、`关注艺人`、`本月概览` 三种类型中单选。
- `下一场活动` 显示最近 planned 活动和倒计时；没有未来活动时显示添加活动入口。
- `关注艺人` 第一版只选择 1 位艺人，展示头像、名称、年度活动数、拍立得数和下一场相关活动。
- `本月概览` 标题使用当前月份记录，例如「7 月记录」，展示已完成、计划中、拍立得人数和拍立得张数，点击进入统计页当前月份。
- 置顶信息选择不自动隐藏下方同类功能卡片。
- 下方「未来活动」功能卡片只在置顶类型为 `下一场活动` 时排除最近 planned 活动；选择 `关注艺人` 或 `本月概览` 时继续展示完整未来活动列表。

### HomeUpcomingHero

文件：`src/components/HomeUpcomingHero.tsx`

- 用于置顶信息的 `下一场活动` 类型。
- 存在最近 planned 活动时渲染；无未来活动时由首页渲染置顶添加活动空态。
- 背景 `colors.heroBg`，圆角 22，padding 14，`marginBottom 18`。
- 左侧倒计时块 72x72，圆角 16。
- 右侧包含 eyebrow「最近活动」、标题、时间地点副标。
- 单推命中时底部出现 callout，包含 `OshiAvatar`、文案「这场活动有你推参加哦」、单推名和 `OshiBadge`。
- 整卡点击进入活动详情，`activeOpacity` 0.88。

倒计时文案：

| 条件 | 主值 | 标签 |
|------|------|------|
| 今天且有时间 | `HH:MM` | 今天 |
| 今天无时间 | 今天 | 别忘了去现场 |
| 明天 | 明天 | 准备出发 |
| 其他未来日期 | `N` | 天后 |
| 今天已过且有时间 | `HH:MM` | 已结束 |

### HomeDashboardCards

文件：`src/components/HomeDashboardCards.tsx`

首页 dashboard 卡片应是行动入口，不做纯装饰。

- 关注艺人卡是单个卡片，卡片内最多展示五位关注艺人、下一场活动和记录摘要。
- 最近完成以「模块标题 + 容器卡 + `EventRow` 行列表」展示，显示数量上限由 `/settings/home` 配置，支持指定数量或全部。
- 默认仅开启未来活动、最近完成和电子切册速览；关注艺人和本月概览保留在未启用区。
- 本月概览保留外层 section 标题，卡片内标题使用当前月份记录，例如「7 月记录」，展示已完成、计划中、拍立得人数和拍立得张数。
- 电子切册速览展示总数、本月新增和最近图片。
- 除本月概览的一行月份标题外，首页 dashboard 卡片不在卡片内部渲染模块标题；标题、计数和右侧 action 由首页外层模块标题统一承载。
- 卡片圆角 16，padding 15，边框 `divider`，轻阴影。
- `/settings/home` 使用「置顶信息」分区承载固定英雄卡配置，使用 `Sortable` 列表承载功能卡片排序，并以「已启用 / 未启用」分区线表达显示状态。功能卡片拖到分区线前即开启，拖到分区线后即隐藏；未启用卡片使用 muted 背景、文字和图标置灰。

### 首页时间线

计划活动按 `src/utils/homeTimeline.ts` 分组。组标题使用小圆点、标题、日期范围和横线，避免重复大卡片标题。

- 首页未来活动时间线卡片使用 `AnimatedPressable`：`HomeTimelineEventCard` 可用 `pressedScale 0.975`。
- 最近完成区使用 `EventRow` 行列表，外层包圆角 16、边框 `divider`、轻阴影的容器卡；第二行左侧为日期（`M月D日`，不含年份）与地点（城市 · 地点，无前置图标），右侧为评分星级（`EventRatingStars`）。最近完成可配置为全部展示。
