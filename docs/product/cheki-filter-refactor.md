# 电子切册筛选与规格重构需求

本文档冻结电子切册筛选与拍立得规格重构的产品需求。实现状态以代码和测试为准；若实现需要改变本文档中的产品语义，应先重新确认需求。

## 1. 目标

- 让电子切册的筛选条件与 Record / Item 两层数据模型一致。
- 将 Record 浏览和 Item 浏览拆成互不干扰的两套模式与筛选状态。
- 通过默认值、快捷选择和渐进披露降低筛选认知负担。
- 用受控的 Item 规格替代任意展示比例，并由规格派生图片展示比例。

搜索能力不在本轮重构范围内；保留当前搜索行为，不把搜索词并入新筛选状态。

## 2. 领域与数据模型

### 2.1 Cheki Item Spec

`spec` 是 Cheki Item 的单值受控属性，不是标签，也不拆成尺寸与方向两个字段。本轮不支持自定义规格。

| ID | 用户文案 | 展示宽高比 |
|---|---|---:|
| `three_inch_portrait` | 三寸竖版 | 54 / 86 |
| `three_inch_landscape` | 三寸横版 | 86 / 54 |
| `five_inch_portrait` | 五寸竖版 | 86 / 108 |
| `five_inch_landscape` | 五寸横版 | 108 / 86 |
| `square` | 方形 | 1 |

- 默认规格为 `three_inch_portrait`（三寸竖版）。
- App 用户界面、内部枚举和商店文案不使用 `Instax`。
- 数据库升级到 v21：重建 `cheki_items`，直接移除未正式发布的 `display_aspect_ratio`，新增非空 `spec` 与五值 `CHECK` 约束。
- 开发版旧数据统一回填默认规格，不根据旧浮点比例推断。
- 完整备份格式升级；恢复旧备份时忽略 `display_aspect_ratio` 并使用默认规格。

### 2.2 规格录入与展示

- 新建 Record：高级信息默认收起；其中的规格默认三寸竖版，并应用到本次创建的全部 Item。
- 编辑 Record：高级信息中的“新增拍立得规格”只应用于本次新增或因数量增加而创建的 Item，不覆盖已有 Item。
- 编辑 Item：高级信息中可以编辑当前 Item 的规格。
- Record 详情显示规格分布，例如“三寸竖版 3 · 五寸横版 2”。
- 全屏拍立得详情显示当前 Item 规格。
- Record 列表、按艺人视图和相册视图不显示规格文字或徽标。
- 缩略图使用规格派生的宽高比完整展示图片，图片居中、不裁切。Record 详情保持固定三列列宽，缩略图高度可随规格变化并按行换行排列；列表、按艺人和相册视图继续使用稳定网格，不使用瀑布流。

## 3. 浏览模式与视图设置

电子切册包含两个面向用户的浏览模式：

- 记录模式：浏览拍摄或购买批次，包含有图和无图记录。
- 相册模式：只浏览至少有一张图片的实体拍立得。

模式入口仍位于右上角“显示选项”，不新增页面顶部的分段控件。iOS 与 Android 统一使用 Bottom Sheet；选项立即生效并持久化，不提供“应用”按钮。界面文案不显示 Record / Item 等数据模型术语。

视图设置内容：

- 浏览模式：相册 / 记录。
- 相册：按艺人 / 按日期 / 不分组、最新或最早排序、图片大小、按规格或统一比例展示。
- 记录：最新或最早排序、显示或隐藏缩略图。
- 每组选项把默认值固定在最左侧，顺序依次为“相册 / 记录”“按艺人 / 按日期 / 不分组”“最新在前 / 最早在前”“大 / 中 / 小”“统一比例 / 按规格”“显示 / 隐藏”。

默认值为：相册模式、按艺人、大图、统一比例、最新在前；记录模式最新在前并显示缩略图。相册与记录分别保存排序偏好。旧版 Item / Record 偏好迁移到对应的新模式与选项。

记录模式按业务日期分月显示，月份内与月份间遵循当前排序；未填写日期的记录放入末尾的“日期未填写”，不使用创建时间代替业务日期。相册按日期分组时使用自然日标题；未填写日期的图片同样固定放在最后。按艺人时排序只影响组内图片，不改变单推、收藏和最近活跃优先的艺人组顺序。

## 4. 筛选条件

Record 与 Item 各自维护独立的已应用筛选和草稿筛选。类别之间使用 AND；同一类别中的多选值使用 OR。

### 4.1 Record 模式

- 日期：日 / 月 / 年 / 自定范围，四者互斥；“全部时间”清除日期条件。
- 艺人：多选。
- 图片状态：单选“无图片 / 部分添加 / 已完整”。状态始终基于完整 Record 的全部 Item 计算。
- 更多：只提供正向开关“已关联活动”“已有备注”“有背签”。
- “已有备注”命中 Record 备注非空，或任一 Item 备注非空。
- “有背签”命中任一 Item 有背面图片。
- 支持来自活动详情的精确活动条件。

### 4.2 Item 模式

- 结果只包含至少有一张图片的 Item。
- 日期：使用所属 Record 日期。
- 艺人：使用所属 Record 艺人。
- 规格：当前 Item 的 `spec`，多选。
- 更多：只提供正向开关“已关联活动”“已有备注”“已收藏”“有背签”。
- “已有备注”只判断当前 Item 备注；“已收藏”只判断当前 Item。
- “有背签”判断当前 Item 是否有背面图片。
- 所有 Item 条件必须命中同一个 Item。
- Item 按艺人视图显示符合条件的 Item 数；相册只展示符合条件的 Item。
- 从结果进入 Record 详情后仍展示完整 Record，不展示筛选后的 Item 子集。

### 4.3 艺人选择

- 复用现有艺人选择器，不在筛选页顶部展开全部已选艺人 chip。
- 提供“单推”和“收藏艺人”批量快捷选择：若快捷集合未全部选中，点击后补齐全部；若已全部选中，点击后移除全部。快捷操作后仍可逐个增删。
- 艺人筛选只匹配 Record 直接关联的艺人，不沿普通所属或正式团体履历扩展。
- 顶部摘要：单个艺人显示名称，两个及以上显示“艺人 N 位”。筛选按钮角标按启用的筛选类别数计算，而不是选项数。

### 4.4 日期选择

- 日：选择一个自然日。
- 月：年份导航与 12 个月网格。
- 年：每页 12 年。
- 自定范围：选择起止日期。
- 打开日期子选择器时，主筛选 Sheet 临时收起；子选择器确认后恢复主 Sheet 并写入草稿，取消则恢复且不修改草稿。
- 日期子选择器的确认不直接应用筛选。

### 4.5 筛选面板布局

- 日期之下为「其他条件」，允许按语义分成连续的 chip 组：Record 的图片状态、正向快捷条件，以及 Item 的规格。每组 chips 在页面内换行、不横向滑动；组间只用间距或小标题区分，不折叠。
- “已关联活动”“已有备注”“有背签”属于正向快捷条件；Item 模式另含“已收藏”。Record 模式的“图片状态”单选。每组可提供“全部”chip 清除该组条件，也可再次点击已选项取消。
- 规格组位于「其他条件」末尾，多选；“全部”chip 清除全部规格。
- “单推”“收藏艺人”批量快捷 chip 位于「艺人」分区内、选择器上方；整批已选中时 chip 呈选中态，再点整批移除。

## 5. 筛选交互状态机

- 打开筛选 Sheet 时，将当前模式的已应用筛选复制为草稿。
- Sheet 内修改不刷新列表。
- 底部只显示“应用”；点击后提交草稿并关闭。
- 滑动关闭、点击遮罩、系统返回均静默丢弃草稿。
- “重置”只重置当前模式的草稿，仍需点击“应用”。
- 切换大模式时恢复目标模式各自的已应用筛选。
- 进入详情再返回、离开电子切册后在同一 App 会话中返回，均保留筛选。
- App 重启后清空筛选，不写入 AsyncStorage。
- “其他条件”直接展示在日期之下，不提供折叠；内部允许按图片状态、快捷条件和规格分组，各组 chip 在页面内换行。
- 顶部活动摘要按类别压缩展示，并可单独清除。精确活动条件显示“活动：活动名”；存在精确活动时不重复显示“已关联活动”。

## 6. 深链行为

- 日历、统计、活动详情进入电子切册时强制切换到 Record 模式，只初始化 Record 筛选，不覆盖 Item 筛选。
- 日历可传入精确日期与艺人；统计可传入日期区间与艺人；活动详情可传入精确活动。
- 首页无条件进入时恢复本次 App 会话中的上次大模式。

## 7. 本轮交付边界

包含：

- v21 schema migration、完整备份版本升级及旧备份兼容。
- Record / Item 两套 Repository 筛选能力。
- 双模式与独立会话级筛选状态。
- iOS / Android 统一视图设置 Bottom Sheet。
- 日 / 月 / 年 / 自定范围日期选择。
- Record 表单、Item 编辑、Record 详情、全屏详情的规格支持。
- 基于规格的缩略图比例。
- 数据库迁移、Repository/筛选工具、偏好重置和关键组件测试。
- 拍立得数据模型、UI/UX 与 QA 文档同步。

不包含：

- 搜索重构。
- 标签、自定义规格。
- 统计页与其他页面的筛选重构。
- 排序算法调整。
- 在 Item 模式展示无图片 Item。

## 8. 验收重点

- 筛选草稿在未点击“应用”时不会改变结果，任何非提交关闭方式都会丢弃草稿。
- 两个模式的筛选互不覆盖，深链只初始化 Record 条件。
- Record 图片状态与备注口径、Item 备注与收藏口径符合本文件定义。
- v20 数据升级后 Item 数量、价格、备注、收藏、图片与关联均保留，规格统一为默认值，旧比例列不存在。
- 新旧备份均可恢复；旧备份不会因缺少 `spec` 失败。
- 所有新 UI 支持浅色/深色、Android 返回键和至少 44×44 的触控目标。
