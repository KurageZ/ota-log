# 活动详情分享功能设计

> 状态：已实现。
>
> 本文定义活动详情页分享功能的产品边界、交互、分享文案、图片内容与验收标准。后续如有新取舍，应先更新本文档。

## 背景

活动详情页已经保存活动名称、公开演出链接、一个或多个场次，以及活动资料图。用户需要把这些公开信息快速分享给他人，但不同场景对分享载体的要求不同：聊天中更适合复制链接或简短文本，社交平台更适合直接分享一张具有活动视觉信息的图片。

ota_log 是本地优先应用。活动 ID 和数据只存在于本机 SQLite，App 内 Deep Link 无法让另一位用户获得同一条活动数据，因此本功能不把 App Deep Link 作为跨用户分享链接。

## 目标

- 在活动详情页提供清晰、易发现的分享入口。
- 有公开演出链接时，可以快速复制活动名称和链接。
- 没有公开演出链接时，仍可复制一段简洁、可直接粘贴的活动信息。
- 生成适合社交平台发布的 9:5 竖版分享图片。
- 分享图片优先呈现活动资料图，同时保证名称、时间和地点可读。
- iOS 与 Android 使用一致的产品规则。
- 分享过程不泄露用户的个人记录。

## 非目标

- 不生成或分享 App 内活动 Deep Link。
- 不上传活动数据，不生成可在网页访问的活动页面。
- 第一版不提供多套图片尺寸或模板。
- 第一版不提供生成前预览、模板编辑、字段选择或主题选择。
- 除公开的参演艺人头像和分享者的头像、名称外，分享图片不包含状态、票价、实际支出、回顾评分、备注、Setlist、同行者、拍立得记录等信息。
- 不为本功能新增资料图封面选择、类型标记或排序能力。

## 入口与操作菜单

活动详情页顶部导航栏增加分享图标，与编辑操作并列。

点击分享图标后打开操作菜单。菜单包含两个动作：

1. 简单分享。
2. 生成分享图片。

简单分享的名称根据数据动态变化：

| 条件 | 菜单文案 | 操作结果 |
|------|----------|----------|
| `event.url` 为非空有效文本 | `复制活动链接` | 复制活动名称和公开演出链接 |
| `event.url` 为空 | `复制活动信息` | 复制活动名称、日期时间和地点 |

生成分享图片的菜单文案固定为 `生成分享图片`。

## 简单分享

### 有公开演出链接

复制内容由活动名称和 URL 组成：

```text
{活动名称}
{URL}
```

复制成功后显示非阻断的短暂反馈：`活动链接已复制`。

### 没有公开演出链接

复制内容仅包含核心公开信息：

```text
{活动名称}
{日期与时间}
{城市 · 场馆}
```

缺失城市或场馆时只保留已有部分。时间或地点均未填写时，分别使用 `时间待定` 和 `地点待定`，不留下难以理解的空行。

多场活动按场次顺序逐项列出日期时间和地点，具体文本格式与分享图片使用同一套格式化规则。

复制成功后显示非阻断的短暂反馈：`活动信息已复制`。

## 分享图片

### 基础规格

- 固定 9:5 竖版比例（高:宽）。
- 上方海报区域固定为 4:3 竖版比例（高:宽），下方追加应用生成的信息区。
- 使用固定浅色模板，不跟随 App 当前深浅模式或主题色。
- 生成完成后进入全屏预览页（复用拍立得贴纸相机的「已生成」预览交互），可保存到相册或打开系统分享面板；保存后按钮显示「已保存」。
- 分享文件使用临时缓存，不作为用户资料图永久保存；保存到相册的是系统相册中的独立副本。

### 图片内容

分享图片只包含：

- 活动名称。
- 日期与时间。
- 城市与场馆。
- 第一张可用的活动资料图；没有可用资料图时使用无图模板。
- 参演艺人（团体）头像。
- 分享者头像、名称和「分享给你」文案。
- 底部右侧的品牌标识。

不包含除分享者公开资料外的个人记录。

### 资料图规则

当前资料图没有独立的封面字段或手动排序字段。因此，“第一张资料图”指资料图查询顺序中的第一张，即最早添加的资料图。

- 普通横图或竖图：居中裁切并铺满图片区域。
- 极长或极宽图片：完整显示，允许出现与模板协调的留白，避免裁掉时间表等关键信息。
- 第一张资料图无法读取或解码时，不让整个分享流程失败；继续尝试下一张资料图。
- 所有资料图均不可用或活动没有资料图时，使用品牌色渐变或几何背景。

### 布局规则

- 无论单场或多场，资料图区域均保持 4:3 竖版比例。
- 活动名称优先完整显示并动态缩小字号。
- 标题达到最小字号后，最多显示两行，超出部分省略。
- 品牌标识固定放在底部右侧，使用圆角 App 图标和 `ota log` 字样。
- 地点下方紧跟一行较大的圆形参演艺人（团体）头像，不将头像行固定在信息区底部。从左到右按「用户单推或其所属团体 -> 收藏 -> 普通」排列，同一优先级保留活动原有顺序。
- 艺人头像使用固定大尺寸，一行最多展示 10 个，不为容纳更多艺人而缩小。超出时在第 10 个头像右下角叠加 `+N` 圆形角标。
- 底部左侧显示分享者头像与「{userName} 分享给你」，与右侧品牌标识保持同行。
- 品牌标识应清晰可辨，但不得抢占活动名称和场次信息的视觉层级。

项目当前没有独立 Logo 或 wordmark 文件。第一版将现有 App 图标视为 Logo，并与文字 `ota log` 组合使用。

## 场次信息规则

### 排序与数量

- 场次沿用活动详情页和 Repository 的既有排序结果。
- 分享图片只展示第一场的日期、时间和地点，不在图片中展示其他场次信息。
- 简单分享文本不受图片画布限制，按既定顺序列出全部场次。

### 日期与时间

- 单日场次显示开始日期。
- 结束日期与开始日期不同时显示完整日期范围。
- 优先显示 `OPEN` 和 `START`。
- 同时存在时显示 `OPEN HH:MM · START HH:MM`。
- 只有其中一个时间时只显示已有时间。
- 两者都不存在时显示 `时间待定`。
- 第一版不在分享内容中展示结束时间。

### 地点

- 城市和场馆同时存在时显示 `城市 · 场馆`。
- 仅存在一个字段时只显示已有字段。
- 两者都不存在时显示 `地点待定`。

## 状态与异常处理

- 生成图片期间应避免重复触发操作，并显示明确的忙碌状态。
- 复制失败、图片生成失败或系统分享不可用时，使用项目统一失败提示。
- 用户取消系统分享不视为错误。
- 资料图文件缺失或损坏时按资料图降级规则继续生成。
- 无链接、无时间、无地点、无资料图的活动仍允许生成分享图片。
- 分享完成或取消后，可尽力清理本次生成的缓存文件；清理失败不应影响用户完成分享。

## 可访问性与双端一致性

- 分享图标必须提供明确的 accessibility label，例如 `分享活动`。
- 操作菜单项目不能只靠图标区分。
- 复制完成提示和失败提示应可被辅助技术感知。
- iOS 与 Android 的菜单视觉形式可以遵循各自平台惯例，但文案、字段口径和结果必须一致。
- 生成图片的浅色模板必须在系统浅色和深色模式下都保持可读。

## 验收标准

### 入口与简单分享

- 活动详情页顶部显示分享入口，且不影响现有编辑入口。
- 有公开演出链接时，菜单显示 `复制活动链接`。
- 复制链接的内容包含活动名称和原始 URL。
- 没有公开演出链接时，菜单显示 `复制活动信息`。
- 复制活动信息包含活动名称、全部场次的日期时间和地点。
- 缺失时间或地点时使用明确的待定文案。
- 复制成功后显示与实际动作匹配的短暂反馈。

### 图片生成与分享

- iOS 和 Android 都能生成 9:5 浅色竖版分享图片，进入预览后可保存到相册或打开系统分享面板。
- 图片上方以 4:3 竖版区域展示海报，下方展示活动名称、日期时间、地点、参演头像、分享者资料和品牌标识。
- 参演头像按单推（或所属团体）、收藏、普通的优先级从左到右排列。
- 分享者头像和名称位于左下角，并与右下角品牌标识同行。
- 单场与多场活动都保持 4:3 海报区，图片信息区只使用第一场的日期、时间和地点。
- 多场活动不在分享图片中显示其他场次信息。
- 普通资料图可裁切铺满，极端长宽比资料图不会被破坏性裁切。
- 无图、坏图、长标题、多场、跨日、缺时间和缺地点时仍能生成可读图片。
- 品牌标识以圆角 App 图标和 `ota log` 组合呈现，并位于底部右侧。
- 取消系统分享不会显示失败提示。

### 回归检查

- 活动详情页原有链接打开、长按复制、编辑和返回行为不受影响。
- 分享功能不修改活动或资料图数据。
- 分享生成物不会出现在活动资料图列表中。
- 浅色和深色系统模式下都能正常操作分享入口和菜单。

## 实现提示

以下内容是实现约束，不改变上述产品口径：

- 简单分享应复用统一的活动时间与地点格式化工具，避免详情页、复制文本和分享图片出现不同口径。
- 图片生成可复用项目已有的离屏图片编码和缓存文件写入方式。
- 系统图片分享应复用现有 `expo-sharing` 能力，并在调用前检查可用性。
- 资料图 URI 可能因文件缺失或容器路径变化而不可用，解码必须有降级路径。
- 中文标题和地点必须在 iOS、Android 的实际生成图片中验证字体、字重、换行和省略行为。
- 图片生成逻辑应与页面组件解耦，以便对场次格式化、布局决策和异常降级进行测试。
