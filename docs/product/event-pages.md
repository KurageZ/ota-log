## 活动详情和表单

### 活动详情

文件：`app/events/[id].tsx`

- 顶部导航栏提供分享入口，与编辑操作并列。点击后通过底部操作菜单选择简单分享、生成分享图片或添加到日历：有演出链接时仅复制链接，无链接时复制活动名称、全部场次时间和地点；生成图片使用固定浅色 9:5 竖版模板，上方以 4:3 竖版区域展示第一张可用资料图，下方展示活动信息、按单推与收藏优先级排序的参演艺人头像，并在底部同行显示分享者资料与 App 标识。生成完成后进入全屏预览页，可保存到相册或打开系统分享，预览交互与拍立得贴纸相机「已生成」页一致。完整字段、降级和验收口径见 `docs/product/event-sharing.md`。
- 计划中 / 心愿单且起始日期不早于今天的活动，在概览卡时间地点信息的右侧显示倒计时，当天显示「今天」；多场活动按起始日期计算。
- 多场的未完成活动从上到下为「活动概览 / 场次 / 详情 / 时间表 / 出演者 / 我的记录 / 更多」；已完成活动将「我的记录」前移到时间信息下方，其余顺序不变。活动概览依次显示活动名、单独一行的单推命中提示、同一行左对齐的状态与右侧内容，右侧按状态展示：已完成显示星级，已取消不显示；概览不显示演出链接，链接归入「更多」。状态保持 32px 高的紧凑胶囊，详情页评分使用约 23px 星标和固定间距，整行最小高度 44px。单推命中药丸不显示心形，评分不显示额外的操作提示。
- 时间地点信息固定为三行：第一行日期与星期（`YYYY-MM-DD` 横杠格式 + 中文星期，例如「2026-08-14 周五」，16px 加粗），第二行时间前置 `time` icon，第三行地点前置 `eventLocation` icon，后两行使用 14-15px 的次级正文；没有时间时第二行显示「时间待定」。单场活动把时间与地点通过轻量分隔线直接合并到概览卡中，不再显示独立 Section，也不显示「场次」概念。多场活动在概览卡内用轻量分隔线显示日期范围摘要：起始与结束日期（同一场次或同一天只写当天，含星期，例如「2026-08-14 周五 – 2026-08-16 周日」），不显示时间信息；地点全部一致时显示该地点，不一致时显示第一个地点并追加「 等多地」。逐场详情使用「场次」Section，场次行采用 EventRow 式紧凑布局（标题 + 单行元信息），日期 / 时间 / 地点只在场次间存在差异时逐行展示，完全一致则不展示（例如所有场次同一天时行内不重复日期）。计划中 / 心愿单且日期不早于今天的活动，在概览卡时间地点信息右侧垂直居中显示倒计时，当天显示「今天」，其余显示「X 天」，字号 20 / 字重 900 / accent 色；单场占满三行高度，多场按起始日期计算。
- 详情页底部固定显示「更多」Section（不折叠）：有结束时间或结束日期时按场次展示「结束信息」卡片，有演出链接时展示「演出链接」卡片；两者都没有时显示「还没有更多信息」。
- 原「资料图」更名为「详情」，紧跟时间与地点；先展示资料图，展开后先显示演出详情文本，再显示带顶部分隔线的「展开详情 / 收起详情」入口。详情页不显示图片数量和添加入口，新增资料图统一进入编辑活动。
- 出演者默认展示排序后的前 8 位，优先级依次为单推艺人、单推所属团体、收藏艺人、收藏艺人所属团体和其他出演者；超过 8 位时通过按钮展开或收起其余出演者。
- 系统日历入口放在分享菜单的「添加到日历」（位于「生成分享图片」下方）；单场活动直接添加，多场活动先弹出场次选择，避免只写入代表场次。场次行本身不再提供独立日历按钮。
- 有结构化时间表时，Section 标题只显示「时间表」，不显示条目数。条目从左到右依次为约 100px 的时间列、垂直居中的关联艺人头像（如有），以及由名称和备注组成的两行文本；未关联艺人时使用演出内容作为名称兜底，名称为空时不渲染空文本行，备注直接顶齐。只有一个场次含时间表时直接展示，且场次名称为空时不为标题保留空间；多个场次含时间表时，每个时间表使用场次名和日期作为标题，未命名场次只显示日期，并可分别展开或收起。
- 详情页模块标题放在卡片外，使用 SectionLabel/SectionHeader 风格；卡片内部只在需要解释独立信息块时使用标题，不使用左侧竖线。
- 「我的记录」顶部并列展示「票价 / 拍立得支出 / 总支出」三张紧凑卡片；票价沿用活动的 `actual_expense` 存储值，拍立得支出汇总有图与无图补录金额，总支出为两者之和。其后展示拍立得、备注和 Setlist；没有拍立得记录时只显示空态文案，不额外显示「去添加」按钮，新增入口保留在卡片标题行。
- 资料图和拍立得查看使用全屏 Modal。

Mini countdown：

- 位于活动概览卡时间地点信息的右侧，垂直居中，使用 20px/900 的 `accent` 文本；单场占满三行高度。
- 文案为「X 天」；当天显示「今天」。
- 仅在状态为计划中或心愿单、日期不早于今天时展示；已完成、已取消或日期已过不展示。多场活动以起始日期计算。

### 活动表单

文件：`src/components/EventForm.tsx`

- 新建活动页保留底部保存按钮。
- 编辑活动页通过 header 按钮触发 `EventFormHandle.submit()`，表单自身传 `hideSubmitButton`。
- 活动表单按「活动信息 / 时间与地点 / 出演者 / 详情 / 我的记录」分组，Setlist 卡片之后是「高级」展开入口；「时间与地点」标题保持不变，多场活动在 section 内逐场展示，单场活动不出现「场次」概念。模块标题放在卡片外，卡片内部遵守「Section / 卡片 / 字段」层级，普通输入项使用字段标签。
- 「活动信息」只包含活动名称和状态，保持为紧凑的活动概览。
- 表单默认以单场模式展示一组时间与地点；多场次属于高级功能，在「高级」的「场次」section 内提供「添加其他场次」入口，并提示场次是该活动下的一个子活动。点击后把已填的时间与地点作为第一个场次进入多场编辑；多场时允许新增、删除和排序，删到只剩一场时自动回到单场模式。活动本身已包含多个场次（如导入数据）时，「场次」section 直接代替「时间与地点」出现在主流程，逐场展示并可直接新增场次，「高级」内不再重复「场次」。
- 每个场次的日期、开场时间和开演时间同一行展示，城市和场馆在下一行；结束时间和结束日期通过卡片底部默认关闭的「补充结束时间」入口展开后在同一张卡片内填写。多场时卡片头部是场次名称输入框，可直接修改名称。新建过程中添加的多场次逐场展示在「高级」的「场次」section 并隐藏「时间与地点」；活动已有多个场次时以「场次」section 代替「时间与地点」逐场展示在主流程。
- 活动展示卡片使用明确标签展示时间；同时有开场和开演时间时完整显示「开场 HH:MM · 开演 HH:MM」，旧单时间数据按开场时间显示。
- 出演者紧跟时间与地点之后。时间表收进默认关闭的「高级」，展开后每个场次默认显示「添加时间表」入口，添加后可编辑和排序扁平条目。编辑条目保持两行紧凑布局：第一行是演出内容与排序/删除控件，第二行是起止时间与备注；「添加条目」放在最后一条之后。条目只要求演出内容、开始 / 结束时间和备注，并可选关联当前活动的出演者。
- 「详情」包含两张卡片：活动资料图，以及演出链接和演出详情；后两者不再放入「高级」。
- 输入演出内容时自动匹配当前活动已选出演者，点击匹配结果会把艺人名称填入内容并关联该艺人，输入框内显示艺人头像作为匹配指示，可点击头像解除关联；不点击匹配结果则保持不关联。
- 场馆保持文本输入，输入部分名称时显示历史匹配建议；不提供「沿用上一次地点」。
- 删除已有场次前提示其时间表会在保存后同时删除。
- 「我的记录」包含实际支出、回顾评分、备注和 Setlist；回顾评分只在已完成状态出现。
- 「高级」按展开入口样式设计（分隔线 + 居中「高级 / 收起」），不当作独立 section；展开后包含「场次」（单场入口或新建过程中添加的多场次）和「时间表」，「时间表」保持逐场卡片。活动已预填多个场次时「场次」已代替「时间与地点」出现在主流程，「高级」只保留「时间表」。新建页面默认收起；编辑页面只有在活动已有多个场次或时间表内容时才自动展开，否则保持收起。
- 演出公告解析不做艺人名称归一化，只将原始 `artist_mentions` 交给匹配层。
- 「解析公告 / 确认出演者」复用统一 Bottom Sheet，主操作与次操作固定在底部；确认页可「返回解析」并保留已输入的链接和文本。点击遮罩、下滑或 Android 返回退出创建；解析请求在退出后返回的结果不再展示提示或打开创建页。确认出演者写入期间禁止关闭和重复提交。
- 公告和第三方来源的公开票价不自动写入「实际支出」。
- 出演者区域使用 chip、搜索列表、多选和快速新建。
- 错误提示统一走 `failureAlert` 的结构。

### 公告链接与文本解析

- 微博和 iEvent 链接继续使用各自的专用抓取流程；其他独立 HTTP(S) 链接提取公开网页正文或纯文本，再调用与粘贴公告正文相同的本地规则解析器。
- 同时填写公告链接和公告文本时，优先解析文本，合法链接保留为活动来源；正文中包含链接仍按正文解析。
- 普通网页抓取不携带登录凭据、不执行 JavaScript，不自动下载图片；请求超时为 15 秒、响应上限为 3 MB。无法抓取时保留输入，可粘贴正文重试或手动创建。
- HTML 提取保留段落和字段边界，移除脚本、样式、导航等内容。规则尽力提取标题、日期、场地、出演者及时间，不承诺识别全部字段；用户在草稿中核对修改。
